IMPERIA COLD WAR: CIA and KGB Dossiers
=====================================

Current design and implementation: 24 October 2026. This revision supersedes the mechanics catalogue and custom negotiation proposals in `USA_SOV_MENU_DESIGN.md` and `USA_SOV_DETENTE_CONCEPT.md`. Those earlier files remain research/design history. National focuses remain outside scope. The native first implementation is generated by `tools/superpower_dossier/build.py`; its behaviour, limits and validation artifacts are documented in `tools/superpower_dossier/README.md`.

Visual correction: the approved reference is `intelligence-dossiers.html`, with `dossier-cia-preview.png` and `dossier-kgb-preview.png` as the inspected compositions. The first native version incorrectly kept a static CIA paper/launcher while changing only text and did not reproduce the approved typography or file-index layout. The subsequently approved financial-intelligence extension uses existing civilian intelligence and recipient networks: 60% civilian intelligence on the provider or 50% network strength in the recipient reveals sensitive detail. Public commitments and own records remain available. Completed foreign payments and interference are observed only with sufficient access at that time, with no retrospective payment discovery. These rules supersede the earlier no-gating description below for financial details; they introduce no separate agency-strength statistic.

Navigation correction: the intermediate action instruction modal and its dimming overlay are removed at the user's request. Each response button checks the current recipient, closes the file and focuses that country's capital through the supported native `goto_state` effect. The player right-clicks the country to open diplomacy; the action path is in the button tooltip. No supported effect to open targeted diplomacy or synthesize that right-click was established. This supersedes the concept's instruction modal. A full game restart loads the revised interface and private fonts.

## Binding mechanic boundary

This menu presents existing game actions. It introduces no strategic-force ceiling, diplomatic currency, tension score, trust statistic, assistance modifier, guaranteed intelligence discovery, custom counterproposal rule or automatic bilateral disarmament.

The new work is a country-specific dossier interface and an observation view. Actual gameplay remains in the existing native, MD and Imperia diplomatic actions. The dossier must not copy their effects into a second transaction handler, add extra rewards, waive normal requirements, command another player or interpret opening a report as consent.

SALT, INF and START cannot be represented as new numerical restrictions while claiming to use only existing mechanics. They are therefore absent from this revision's executable action catalogue. Historical discussions do not establish a supported current game action.

## Visual direction

The American player sees an executive file with a tan folder, cream paper, CIA seal, typed routing line, dark green action buttons and a red Top Secret stamp. The Soviet player sees a registry file with a red-brown cover, KGB shield/sword emblem, a red file rule, a Strictly Secret stamp and registry markings. All newly authored labels and stamps are English.

Both are government dossiers prepared by the intelligence service for the player. The CIA or KGB framing does not give that agency independent control over diplomacy, armies or another government's decisions.

Country perspectives are shown as separate preview variants. In the game the actual USA/SOV identity selects the presentation; a player does not acquire another country's controls by changing a visual variant.

Three folder tabs:

- Field Reports: dated, known American/Soviet activities. The selected report shows actor, recipient, evidence and observed extent, followed by relevant existing actions.
- Diplomatic Offers: a bounded correspondence log from the existing MD trade and Imperia money-transfer procedures. Native send/response windows retain their prospective effects and recipient controls. The dossier does not duplicate those windows or claim that a sent log entry is still pending.
- Current Commitments: the player's own actual lend-lease, volunteers, attaches, sanctions and accepted native agreements. Only the owning country receives its withdrawal/cancellation action.

Example campaign entries are illustrative, dated October 1973. They are not observations of a live game or automatic historical incidents.

## Existing trade effects, not invented bonuses

The native `propose_improved_trade_agreement` effect applies the registered `mutual_trade_agreement` and `mutual_trade_opinion` in both directions. `common/opinion_modifiers/Trade Relations.txt:61` defines +100 trade opinion and +25 ordinary opinion. These are the existing game's values.

It also calls the real influence helper with a base change of 1 for each country in the other. `common/scripted_effects/00_influence_scripted_effects.txt:1057` applies influence/defence modifiers and remaining headroom. The concept identifies +1 percentage point as the base change. The installed dossier must use the real scoped native preview/calculation; it must not hardcode that base value as every campaign's realized gain.

With By Blood Alone, the existing accepted trade action also breaks the parties' native bilateral embargoes where present. That is not removal of all four Imperia sanction classes. Retain the actual conditional effects.

The real rejection effect registers `reject_trade_agreement` in both directions, defined at -50 opinion with decay 5 in `common/opinion_modifiers/new_opinion_modifiers.txt:383`. Its temporary rejection records must not be promoted into a new blanket player lock. The proposal cost is charged by the native send action and must not be charged again on reply.

The illustrated $0.50 billion transfer is a sample selected amount, not a new price or reward. Existing transfer execution subtracts the chosen amount from the sender and adds it to the recipient.

## Observation policy

The current MD trigger `root_supports_an_enemy_of_this_country`, at `common/scripted_triggers/00_diplo_action_valid_triggers.txt:91`, already uses `has_volunteers_amount_from`, `has_attache_from` and `is_lend_leasing`. Reuse these observable kinds of facts without creating a parallel proxy-war simulation.

An active lend-lease connection proves that a connection exists. It does not establish exact delivered quantities, successful arrival or equipment composition. The implemented report states that limit. Per the implementation request, USA/SOV presence records have no agency/network gates. There is no claim to detect covert operations or to enumerate unrelated countries' private transactions.

The Cuban sanction example maps Soviet support options to Cuba, never to SOV itself. All actions validate the exact sender and recipient; the response target is not simply the actor in the selected report. Sanctions and support remain distinct current game actions.

## Performance and multiplayer

Use one provider for each action: the existing native/MD/Imperia implementation. Do not create a second queued offer, escrow, custom deadline, agreement currency, signature reward or settlement pulse around the same native action. The dossier's extra persistent data should be limited to observation/cache metadata and UI needs.

Trade and money correspondence uses existing send/accept/refuse hooks. Reconcile current country-level presence once weekly for USA and SOV, once for the pair, not once per human or open window. Unhooked changes can therefore take until the next weekly review to appear. No per-frame world sweep, daily province scan, division-position tracker, hidden-view formatting loop or repeating random discovery roll is added.

The UI distinguishes observed correspondence from current native agreement/presence records. Opening, selecting, hovering and reopening cannot pay money or accept an offer. Closing the dossier does not stop the weekly review or correspondence observers. No manually ticked Completed checkbox substitutes for the real mission, support connection or sanction state.

Co-op clients may share country variables. Bind actions to the correct actual country and intended recipient. Native UI selection indices are not safe transaction identities by themselves. Retain the earlier requirements for stale context, simultaneous input, duplicate effect execution, save/reload and rehost verification, but apply them to the real reused action path instead of claiming a separate browser negotiation model proves native synchronization.

Existing does not mean audited for every multiplayer edge case. In particular, the money-transfer provider reads a country-level `gift_size`; its shown execution does not itself establish a complete co-op-safe frozen-price/funding contract. Audit and exercise that native path before adding a direct dossier execution shortcut. This design changes none of its runtime logic.
