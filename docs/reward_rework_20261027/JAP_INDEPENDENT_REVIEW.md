# Japan reward rework: independent source review

Scope: reviewed the staged Japan reward sources against the pre-revision live snapshot at `E:/HOI4_Mod_Tools/mdcoldwar/runtime/reward_rework_20261027/before`. This review covers source and staging only. The staged output is not loaded by the game, so no native tooltip, runtime scope, balance, or multiplayer result is claimed.

## Confirmed defects

1. **Equipment and doctrine bonuses are emitted twice.** In [generate_staged_effects.py](../../tools/japan_1970/generate_staged_effects.py), `effect_preview_body` repeats both bonus loops at lines 165-179 after already emitting them at 158-163; the runtime helper writer repeats the same loops at 271-281 after 264-270. The generated previews are duplicated too. This is a confirmed source/output defect; whether duplicate same-name native bonuses stack or overwrite requires a live-game check. Remove the repeated loops and regenerate both helper and preview output.

## Checks that passed at source level

- Domestic GDP-priced focus transactions put `check_variable = { gdp_total > 0 }` in the same helper limit as the receipt, country/scenario, focus-specific and building guards, before initialization, charge, rewards, and receipt (`generate_staged_effects.py:231-242, 264-287`). The preview is a display-only sibling and computes its charge from the same `gdp_total` share (`:127-136, 188-194`). The visible availability repeats the positive-GDP condition (`:291-297`). This supports the source claim that a missing GDP does not waive the cost and grant the rest of this domestic transaction. Treasury affordability is not separately checked.
- Domestic buildings receive one shared slot per level before construction, in both the generated preview and the guarded runtime effect (`generate_staged_effects.py:181-185, 282-286`). State ownership/control and building capacity are included in the helper guard (`:110-111, 231-237`).
- The ASEAN and Mekong project decisions' `< 5` infrastructure guard is not an over-cap defect: the current MD building provider sets infrastructure `state_max = 6`, and the project grants at most two levels. The staged effect adds two shared slots for two infrastructure levels and three for the Mekong project's infrastructure 2 plus rail terminal 1.
- Party helpers in `staging/party/COLDWAR_JAP_1970_party_effects.txt` check Japan, the scenario, a numeric ruling-party slot, and a per-reward receipt before applying costs or modifier increments. The staged dynamic modifiers use matching party-slot checks, so accumulated variables remain stored while only the current party's modifier is enabled (`build_party_rewards.py:36-46, 76-91`). I found no reapplication path in the generated helper.
- The Article 9 terminal rewards remain one-time guarded in `staging/constitution/effects.txt:102-118`. Abolition changes the active spirit once and sends the USA/Soviet responses from `terminal_effects.txt:2-8`; confirmation grants +75 PP once and a 730-day +5% stability mandate (`:9-11` and `effects.txt:111-118`). Both completion paths are mutually exclusive in the staged focus graph (`staging/graph/focus_tree.txt:598-643`).
- Domestic research bonuses are restricted to `CAT_industry` and `CAT_agriculture` in the source writer (`generate_staged_effects.py:113-119, 158-163, 264-270`); doctrine records use explicit `add_doctrine_cost_reduction` category, uses, and amount; equipment records name the target equipment type and modifier. These are source-shape checks, not proof that MD consumes every emitted category/type as intended.
- The staged regional decisions keep acceptance pending until the recipient selects a state. The actual construction, slot increase, Japan treasury charge, project receipt, and project benefits sit under the pending/not-completed plus Japan-exists and current state owner/control/capacity recheck in each hidden transaction. The separate `effect_tooltip` is prospective. I found no evidence in this source pass that the preview charges or completes the transaction.
