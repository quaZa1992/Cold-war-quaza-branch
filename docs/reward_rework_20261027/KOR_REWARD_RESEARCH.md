# South Korea reward revision: historical and mechanical basis

## Scope and decision

This is a derived reward revision applied after the 300-focus alliance revision. It leaves the approved concept JSON in `docs/design/COLDWAR_KOR_1970` unchanged. The overlay revises 68 existing reward-policy slots and adds 21 explicit project packages across 80 unique existing focus IDs. Seventeen packages add 18 paid building levels; four provide narrow military equipment and finite research specialisation. It does not add IDs, move nodes, change prerequisites or exclusions, or alter party, election, leader, succession, dispatcher, or foreign-consent authority.

The revision replaces weak, generic percentage packages with institution-specific output, technical-learning, finance, rural-development, welfare, civil-military, and readiness outcomes. Drawbacks use supported, already-consumed MD modifiers: credit exposure, higher programme costs, consumer-goods pressure, personnel and equipment expense, slower training, reduced intelligence collection, and political or command constraints. These are balance proposals, not claims that every policy was historically implemented in January 1970.

## Regional projects, party alternatives, and compatible route totals

State IDs are from the January 1970 map: 604 Gyeonggi, 605 Yeongnam, 606 Chungcheong, 607 Honam. Every building level is represented in structured focus data. The existing compiler grants one extra shared building slot for each level, then constructs the building in the same one-time completion transaction. Its focus gate separately checks Korean ownership, control, and native state capacity. Preview and native effect data read the same list. The January 1970 GDP target is about $9.085bn, so prior fixed domestic focus charges of $1bn to $6bn are converted to 0.25% of GDP per old billion, with a 2% cap on the base fraction. Any project increment is added to that base share. For example, Pohang changes from a $3bn fixed charge plus a 1% project increment to one 1.75% GDP charge, or $1.75bn at a $100bn GDP scenario and about $0.15899bn at the 1970 GDP target. Bilateral agreement terms and recipient charges remain unchanged. All converted focuses require positive GDP. No Treasury-affordability gate is added. No project creates uranium, free fuel, or nuclear weapons.

## Implementation and API contract

`COLDWAR_KOR_alliance_revision.load_design()` builds the 300-focus alliance design, then applies `COLDWAR_KOR_reward_revision.py` as an explicit derived reward overlay. `load_design(apply_rewards=False)` remains the alliance-revision baseline for documentation and comparison. The approved JSON is not modified. The overlay has a numeric policy layer (`entries`), a deliberately separate tangible package layer (`projects`), and a domestic GDP cost scale. It adds no focus IDs, changes no geometry or graph condition, and does not take political succession, election, or bilateral consent authority.

A project's building additions are appended to the exact `effects.buildings` payload consumed by the native compiler and preview. Construction is one-time and sits behind the existing paid focus receipt. The compiler grants one shared state slot per added level immediately before that same transaction's building construction, checks state ownership and control and native capacity in focus availability, and exposes both slot and construction effects in native preview. Every positive domestic focus setup charge is converted from its old fixed-billion value to a 0.25% GDP share per old billion, capped at 2% for the base fraction. A project's configured increment is added to that base share. Each focus preview and guarded completion helper now contains one native Treasury charge computed from the total GDP fraction. Positive GDP is a hidden data-validity requirement for all such focuses; the Treasury system's existing no-affordability-gate contract remains unchanged. Bilateral agreement terms and recipient charges are preserved in their separate contract records.

The supported construction types are verified in installed `common/buildings/00_buildings.txt`: `industrial_complex`, `synthetic_refinery`, `energy_infrastructure`, `fossil_powerplant`, `infrastructure`, `agriculture_district`, `offices`, and the existing `arms_factory`. Regional state IDs are the map's 604 to 607 values recorded in this design. Extra capacity is always supplied through the shared slot effect, including infrastructure and power/grid levels.

Equipment bonuses use installed MD family IDs rather than invented hull names: `infantry_weapons_type` and `artillery_equipment` are applied at Changwon; `fighter`, `frigate`, `medium_tank_chassis`, and `artillery_equipment` are used for the relevant air, escort, mobile, and counterbattery options. Their keys are present in the actual loaded equipment definitions. Each reduction is 4% or less, with the rifle discount limited to 6%. One-use technology bonuses use `CAT_industry`, `CAT_small_arms`, `CAT_artillery`, `CAT_aircraft`, `CAT_naval`, and `CAT_armored_fighting_vehicles`, each a category used by installed MD focuses. The single doctrine reward uses the native `land_doctrine` cost-reduction effect shape. The 50% research uses are finite and closely tied to the institution or force family.

The renderer now reads the derived effective design in memory. Its previews show the total GDP-share charge, state, building levels, extra shared slots, ownership/control/capacity conditions, weapon family reductions, and finite research or doctrine counts. The validator authorises only these explicit overlay focus IDs when comparing protected political rewards and keeps the prior gate, receipt, geometry, and foreign-consent assertions. `KOR_reward_change_manifest.json` records before and after policy values for all 68 overlay entries, all 21 project packages, and the converted domestic focus charges. This source record does not claim a native engine tooltip or transaction test.

## Balance limits

- The listed route totals are additive source values for distinct policy slots. They do not model every starting spirit, caps, clamping, party deactivation, global modifier interaction, or state production result.
- Existing project `COLDWAR_KOR_modifier_evidence.json` remains the authority for the exact KOR consumers and units. If the later pipeline finds a modifier without a current consumer, drop or replace it before emission.
- These remain balance proposals for multiplayer. The historic precedents support the direction and costs, not the exact game percentages.
