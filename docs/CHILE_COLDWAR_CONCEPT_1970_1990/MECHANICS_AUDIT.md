# Chile 1970-1990 concept mechanics audit

Audit date: 2026-10-31. Scope: source-level providers, consumers, units and lifecycle patterns for a proposed Chile programme. No loaded mod files were edited. This is a static source audit, not an HOI4 parser or in-game test.

## Version and starting context

The active repository descriptor declares MD Cold War 2.0.3 and HOI4 1.19.* (descriptor.mod:1-15). The installed donor at C:/Program Files (x86)/Steam/steamapps/workshop/content/394360/3374271790/descriptor.mod:1-4 declares MD 2.0.4. Treat the installed donor as the newer comparison, but recheck any relied-upon APIs against the active target before implementation. The target includes an active 1970 setup; the repository has no common/national_focus/05_chile.txt or Chile-specific Cold War tree. Chile's regular 2000 history is separate from the 1970 setup.

In history/countries/CHL - Chile.txt:274-321, the 1970 start sets IMP_1970_historical_politics, writes ruling_party = 1, creates Eduardo Frei Montalva with an expiry of 1970-11-03, and loads mdcw_1970_generic_focus before 1985. The exact visible 1970 party label is IMP_1970_CHL_STARTING_PARTY = Christian Democratic Party (localisation/english/IMP_1970_starting_parties_l_english.yml:34). This matters: a Chile tree must integrate with the 1970 election and leadership flow, rather than assume a permanent Frei government or silently replace the shared generic focus setup.

The native leader-pool routing currently conflicts with the 1970 party registry and must not be copied into a concept. The registry says CHL local ID 1 is PDC, whose 1970 presidential candidate is Radomiro Tomic; ID 3 is the Radical Party (PR), which nominated Alberto Baltra within the Popular Unity coalition; ID 18 is the Socialist Party (PS), associated with Salvador Allende; ID 22 is the Chilean Armed Forces under constitutional commander René Schneider (localisation/english/mdcw_1970_party_registry_l_english.yml:2362-70,2413-27). However, CHL_political_leaders.txt:4-17 routes IDs 1, 3, and 22 to Frei Ruiz-Tagle, Allende, and Pinochet respectively, while mdcw_historical_retirement_alternatives.txt:38-40 expects those same mismatched names. The active start instead creates Eduardo Frei Montalva under PDC/ID 1 through 1970-11-03 (history/countries/CHL - Chile.txt:279-304). Thus the current mapping does not model the actual 1970 starting leader, the registry's Socialist Party ID, or the military party's identity. Correct provider and consumer routing before treating it as a playable party-to-leader system. The audited 1970 setup creates Frei and loads the generic tree; no Chile-specific presidential result/transition event was found in the searched country events and effects. A design that elects Tomic, Baltra or Allende, then permits later Pinochet rule, needs explicit correctly scoped election/coup transitions. No Aylwin character or Chile leader-pool route was found in the searched country character/effect files; a post-dictatorship PDC/Aylwin outcome also needs an explicit party/leader transition. Alessandri is named as PN's candidate in the party-registry text, but no Chile-specific presidential transition was found. Pinochet must only become ruling leader after a military seizure path, not merely because Armed Forces/ID 22 is selected. These are local 1970 party IDs, not vanilla ideology IDs.

## Findings for concept design

1. A Copper Commission or nationalization/reinvestment route should use the economy's custom sector variables and weekly ledger explicitly. There is no native copper resource modifier to grant. The existing shared resource productivity modifier maps every ordinary resource key separately and would require a custom Chile copper-sector consumer.
2. Keep the economic proposal legible as both a one-time setup price and a weekly operating cost when relevant. Use treasury billions for project actions; store recurring flows in weekly MD units. Source budgets in monthly or annual units need conversion before insertion.
3. Place industrial and resource projects in real Chile states only after checking state and province ownership/control and native capacity at completion. Their buildings need the project-mandated shared slots in the same state. The history source is data for the default start and does not replace live ownership checks.
4. Keep permanent national outcomes separate from current-government programmes. Chile has a shared 1970 ruling-party variable and native leader-refresh path. A programme owned by the sitting party needs real party checks in execution and cleanup/reactivation logic; do not hide the branch with party-dependent allow_branch.
5. A proposal to another country needs a real recipient-side acceptance or refusal event. For a long-standing bilateral agreement, reevaluate existence, peace, embargo and each directed sanction class. Preserve one-time fees/assets across suspension and reactivation. Dependents should check the active parent spirit.
6. No negative workforce-size modifier. If copper or industrial specialism is intended to be scarce, express the shortage as a research or productivity cost and match it with an explicit, mechanically effective remedy.

## Confidence limits and unresolved follow-up

This catalogue confirms source providers, key readers and several numerical caps, not balance or rendered tooltip behavior. No in-game parser, January 1970 campaign, party transition, multiplayer recipient event, save/reload or tooltip check was run. The donor and active target minor versions differ. Exact Chile outcomes after the 1970 election, mapping all selectable party IDs, any new copper-sector formula, environmental metric, and bilateral suspension/recovery still need tracing against the supplied concept. Any novel key without a registered provider and a concrete consumer remains unsupported until both are implemented and audited.
