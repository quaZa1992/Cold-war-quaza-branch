# Chile 1970-1990 concept: independent design review

Review date: 2026-10-31. Reviewed `docs/CHILE_COLDWAR_CONCEPT_1970_1990/COLDWAR_CHL_design.json` and its authoring source `build_concept.py` against the current MD/Imperia checkout. Review only: no generator, design JSON, or loaded mod files were changed. This is a static concept review, not a parser or game test.

## Coverage and model integrity

The JSON contains 184 focus nodes, 15 focus groups, 11 party programmes, 52 exclusion pairs, seven starting spirits, five conditional spirits, 14 events, and nine agreement records (eight bilateral, one five-country protocol). The supplied `MODEL_QA.json` reports no missing references, card collisions, or unreachable nodes, and symmetric exclusions. I independently checked that every prerequisite and exclusion ID resolves and all 52 exclusion pairs are reciprocal. Its PASS is model-only; it does not validate emitted script, tooltip rendering, engine scopes, event transitions, or save behavior.

The 1970 party IDs in the groups agree with Chile's scenario registry: Gremial 0, PDC 1, PN 2, PR 3, PCCh 4, MIR 5, DR 14, PS 18, MAPU 19, PADENA 20, Armed Forces 22. The seven start spirits include the historically existing Cartagena membership spirit, so the later Andean member branch is not self-locking at game start. The documented mismatch between the 1970 registry and Chile's native leader routing remains a real integration prerequisite (see `MECHANICS_AUDIT.md`, and `common/scripted_effects/mdcw_historical_native_pools.txt:14804-14832`). In particular, the proposal correctly names PS/18 for Allende, PR/3 for Baltra, and requires Pinochet only after a military transfer.

## First-pass questions, rechecked against the updated concept

The observations below were recorded before the design JSON and browser preview were updated. They are retained for audit history, but each is re-evaluated in the final disposition at the end of this report. The final disposition controls; do not treat a superseded first-pass question as an outstanding defect.

1. **Visible party gates need exact 1970 names.** The initial JSON pass had numeric `party` metadata but no per-node `party_trigger` or `availability_code`; 118 party-programme nodes lacked a descriptive requirement as well (125 nodes have party IDs including slot 0; seven had other descriptive requirements). The integration note said to use existing exact `*_are_in_power` triggers, which is correct for execution: the existing triggers compare the intended numeric `ruling_party` values (`common/scripted_triggers/01_political_triggers.txt:58-63,176-207,267-270,295-326`). The initial review believed native tooltip localization resolved those triggers only through modern Chile ideology labels. The final recheck below shows this was a false finding: the shared scripted-localization path does use the 1970 registry.

   Exact existing trigger names by numeric slot are: 0 `western_autocrats_are_in_power`; 1 `western_conservatism_are_in_power`; 2 `western_liberals_are_in_power`; 3 `western_social_democrats_are_in_power`; 4 `emerging_communist_state_are_in_power`; 5 `emerging_anarchist_communism_are_in_power`; 14 `neutrality_neutral_conservatism_are_in_power`; 18 `neutrality_neutral_social_are_in_power`; 19 `neutrality_neutral_communism_are_in_power`; 20 `nationalist_right_wing_populists_are_in_power`; 22 `nationalist_military_junta_are_in_power`.

2. **Campaign vote needs an explicit candidate-result handoff.** The three campaign options correctly identify candidate, party-support slot and amount (`COLDWAR_CHL_design.json:8753-8795`). The next event describes congressional ratification and installation of the confirmed candidate. The concept still needs to specify how the campaign result is stored/resolved, how a no-majority congress decision consumes that result, and how each outcome routes to the corrected CHL party/leader pool. The candidate fields and `party_support` data are design metadata until emitted as real effects/state and consumed by the ratification event. Do not assume `party_pop_array` alone installs a president. Native scenario start currently assigns ID 1 and Eduardo Frei Montalva (`history/countries/CHL - Chile.txt:300-304`); the registered starting-party label is PDC (`localisation/english/IMP_1970_starting_parties_l_english.yml:34`).

3. **Keep Pinochet-only descendants leader-bound.** The event text and first Pinochet command focus correctly prevent Pinochet from being assumed at the January 1970 start. The concept's runtime integration must add the actual-leader requirement to availability and reward for every Pinochet-specific continuation, not just its entry focus; otherwise a later leader change while ID 22 remains ruling can leave those focuses executable. The parent-only focus requirement must remain visible as a meaningful leadership requirement.

4. **Write the accepted-agreement preview as an explicit focus/inspector payload.** All nine agreement records include both countries' spirit names, modifier deltas, setup charges, weekly costs, research/building rewards, ratification rules, and peace/sanction lifetime conditions (for example `COLDWAR_CHL_design.json:8320-8739`). Each offer focus has an `agreement` reference, but its proposed tooltip currently contains only a helper comment naming the recipient (for example `COLDWAR_CHL_design.json:8350-8370`). No inspector/template or player-facing accepted-effects summary is present in the reviewed folder. Before implementation, resolve each linked agreement into the locked-focus preview and show both countries' full prospective effects, setup and recurring costs, and any building plus its shared slot and research reward. The preview must not execute consent, setup, or recurring charges.

5. **Give the reparations option's weekly cost a declared lifetime.** Both options in `event_truth` carry a 0.001 billion weekly expense; neither has a `duration` or a cost-holder spirit/variable lifecycle (`COLDWAR_CHL_design.json:9130-9164`). The other time-limited event expenses state a duration. Clarify whether reparations are intentionally funded indefinitely or for a fixed term, and specify the exact holder and cleanup/suspension behavior. This is needed to avoid an orphaned ledger charge when its outcome is replaced or later reformed.

6. **Keep economy liquidity claims provisional.** The full set of nine agreements would add 0.012 billion per week in Chile and 0.0075 billion per week across recipients if all were active; Chile-side one-time setup totals 19 billion if every agreement is ratified. A single node's largest one-time focus spend is 6 billion (`pinochet_rescue`). These are not automatically an implausible budget: agreements require independent consent and the focus cash sum of 295 billion double-counts many mutually exclusive routes. But no January 1970 Chile treasury seed was established in the audited history; the 22 billion value is in the regular 2000 history block (`history/countries/CHL - Chile.txt:563`). Keep the concept explicit that all spends use the native debt/treasury model, add its recurring stream to the weekly expense aggregator, and test Chile's debt and interest response with multiple simultaneous offers. Do not treat the 2000 treasury as a 1970 balance.

## Confirmed sound mechanics and scope

- The copper proposal is honestly labeled as a broad resource-export-income proxy, not a native copper resource or copper-only sector. The audited API supports all-resource export income only; this concept does not invent a Chile copper modifier.
- All modifier keys in the design have source providers in the reviewed codebase, including the corrected `training_time_army_factor`. Interest-rate modifiers are percentage-point changes to an annual interest rate before the native clamp, not relative percentages; economic income/cost multipliers are additive fractions to their respective formulas. The detailed key-to-consumer catalogue and source anchors are in `MECHANICS_AUDIT.md`.
- Technology categories used are `CAT_industry`, `CAT_computing`, `CAT_surface_ships`, and `CAT_aircraft`; these are repository category IDs. The prior candidate category strings `construction_tech`, `computing_tech`, `air_equipment`, and `naval_equipment` are absent from this concept.
- The five state IDs used by the building plan exist and are Chilean-controlled in the scenario state history: 463, 468, 472, 949 and 950 (`history/states/463-Southern Chile.txt`, `468-Central Chile.txt`, `472-Atacama.txt`, `949-Tarapaca.txt`, `950-Arica.txt`). Every listed built level is paired with one shared slot in the record. At runtime, separately recheck ownership, control, province destination for province buildings, native building cap and available state slots before charging.
- The 1970 setup has a real Frei Montalva starting character and no Chile-specific presidential transition was found in the audited route. The concept acknowledges corrected party/leader routing as required work, rather than relying on the current bad slot mapping. The military branch also separates constitutional leadership from the Pinochet outcome.
- No negative workforce-size modifier appears in the starting spirits or the focus modifiers. Specialist shortage is represented by a research penalty and a removal/remedy focus; copper remains explicitly broad.
- Native embargo and all four directed Imperia sanction classes are named in the agreement lifecycles. The Andean protocol requires all four counterparties to ratify and suspends all participants' benefits if a required relationship or membership is lost. The bilateral and Andean records say one-time charges/assets do not replay on restoration.
- The report's structural scan found no unresolved focus prerequisites/exclusions or asymmetric exclusion pairs. Focus costs resolve to 14, 21 or 35 days (2, 3 or 5 focus weeks). All weekly literals are within the project's five-decimal limit.

## Final disposition after concept and preview update

Rechecked on 2026-10-31 against the current `COLDWAR_CHL_design.json`, `preview.template.html`, `COLDWAR_CHL_preview.html`, `BROWSER_QA.json`, and `build_concept.py`. This section supersedes first-pass conclusions above where they conflict.

- **Party names and gates are represented correctly in the current concept.** All 125 party nodes now carry `party_trigger` and `availability_code` using existing native triggers, and the inspector renders the registry party name from `PARTIES`. The native party-name path is also correctly overridden by the existing 1970 registry: for CHL, `conservatism_L` resolves through `MDCW_HP_conservatism` to `MDCW_HP_CHL_1_0` (`common/scripted_localisation/00_MD_politicsview_scripted_localisation.txt:11416`; historical party registry lookup in `common/scripted_localisation/mdcw_historical_parties.txt:3544-3547`; availability check in `common/scripted_triggers/01_political_triggers.txt:176-180`). The original claim that these labels were stuck on modern Chilean parties was incorrect because it missed this shared historical-party override. The exact trigger-to-slot mapping in the first-pass table remains valid.
- **The focus inspector now contains complete prospective agreement effects.** The template unconditionally renders “If they accept” on the associated offer focus and shows each country's spirit, signed modifiers, setup, weekly cost, buildings/shared slots and research terms (`preview.template.html:121-125,143`). The Andean offer expands to Chile and all four recipients. `BROWSER_QA.json` reports all nine agreements with the expected two or five sides (`agreementTerms`). This is a design-preview pass, not proof of a live native HOI4 tooltip.
- **Pinochet continuations are leader-bound in the updated concept.** All 17 `pinochet_*` focuses now include both `nationalist_military_junta_are_in_power` and `has_country_leader = { name = "Augusto Pinochet" ruling_only = yes }` in `availability_code`; their lifetime is explicitly leader-bound, except the crisis remedies intentionally have national 365-day lifetimes. The static audit found no unguarded `pinochet_*` node.
- **The campaign now has an explicit election contract.** The data specifies the 1970 campaign, vote, Congress and inauguration calendar; candidate-share calculation; winner, runner-up and confirmed-slot receipts; and a one-time consumption at the November 3 inauguration. It also distinguishes design from current engine behavior (`election_contract.status` says this requires a new Chile integration). The first-pass concern that the model contained no result contract is superseded. The remaining integration work is to implement and verify the native ballot setter and use the corrected CHL leader pool.
- **The reparations options now declare standing national cost lifetimes.** Both 0.001-billion weekly obligations have a `weekly_lifetime` describing permanent national reparations that survive party changes. The unrestricted route adds a lasting-reparations legacy spirit; the limited route retains the limited-accountability burden. This resolves the missing-intent concern. The actual weekly expense read and cleanup/suspension remain runtime work.
- **All 36 modifier keys in the updated design have source matches.** The detailed catalogue in `MECHANICS_AUDIT.md` traces economic keys into their readers; standard modifiers are present in MD/HOI4 modifier sources. The exact training key is `training_time_army_factor` (existing MD use at `common/ideas/05_armenia.txt:865`). The only research categories in this version are `CAT_industry`, `CAT_computing`, `CAT_surface_ships` and `CAT_aircraft`, all present in technology source. No unconsumed copper, environment, workforce-size or other unsupported key is proposed. Copper remains the disclosed broad all-resource export-income proxy.
- **Structure and browser preview checks pass at the current concept level.** `MODEL_QA.json` reports 184 focuses, zero missing references, zero card collisions, zero unreachable nodes and 52 reciprocal exclusion pairs. `BROWSER_QA.json` reports 184 inspected focuses, 14 inspected events, 12 party variants, zero missing art, zero overlaps and zero browser errors; it also reports responsive widths of 1180, 736 and 360 px. These local QA files do not represent an HOI4 engine test. The country-event art is not yet composed; `missingArt: 0` applies to the preview focus art, not finished native-frame event pictures.

## Final minor balance and API pass

Rechecked after the final concept polish on 2026-10-31. No generator, design JSON, or runtime file was edited by this review.

- Cooperative titles now give `stability_factor = +0.04` alongside `agricolture_productivity_modifier = +0.07` (`COLDWAR_CHL_design.json`, node `cooperative_titles`). Family farms instead give +0.10 agricultural productivity with `tax_gain_multiplier_modifier = -0.02`. The cooperative alternative therefore carries a distinct stability benefit, while family farms lead on productivity; neither is numerically dominated across those policy dimensions.
- The design now contains 36 unique modifier keys. The new `imp_sanction_resistance` key is registered as a country percentage (`common/modifier_definitions/mdcw_imperia_globalism_modifiers.txt:22-26`). Its consumer subtracts it from 1 before multiplying diplomatic, financial, economic and military sanction effects (`common/scripted_effects/imp_sanctions_effects.txt:135-153,189-196,241-248,320-322`). A +0.12 modifier therefore scales these calculated sanction effects by 0.88 before the result is clamped to 0..1; it does not prevent the sanction or waive agreement suspension checks. Chile's +0.12 is on the Pinochet security spirit only, and it is now guarded by actual Pinochet leadership.
- Current availability contracts also encode actual Cartagena membership for admission and member focuses, actual military-government flag for the military entry, constitutional-council flag for the constitutionalist path, active crisis idea for Pinochet rescue/loss choices, and a recorded No vote for Pinochet handover. The two restructuring outcomes are national 365-day remedies; their separate availability still requires Pinochet to govern when selecting them. These are contract definitions, not installed effects.
- The election design now corrects the inherited generic calendar: 1964 baseline with a 72-month term, actual September 1970 ballot and November inauguration, then a 48-month transitional presidency after the 1990 handover. It explicitly rejects an accidental generic 1972 presidential election. This is a future integration specification only.
- Final `BROWSER_QA.json` records 184 focus inspections, 14 event inspections, 223 focus links, zero collisions, zero title overflow, 12 party variants, and all nine agreement previews with exact money and signed modifiers verified in the browser DOM. All focus/event browser error and overflow checks are empty. The event art is still not composed, and `engineTested` remains false. All runtime implementation remains deferred.
