# Greek Enosis and Cypriot territorial settlement: native mechanics audit

Read-only feasibility note for a proposed Greece focus-path ending. No runtime or history files were changed. The original draft lacked territorial outcomes; a later concept build now includes both offers, the Turkish reaction window and delayed civil integration. The final-build review is recorded below.

## Native effect support

- `annex_country` is documented in country scope, with a target parameter and optional `transfer_troops = yes` used in native scripts. The installed effect reference is `E:/SteamLibrary/steamapps/common/Hearts of Iron IV/documentation/effects_documentation.md:2495-2498`; local examples include the FSA formation in `events/00_arab_spring.txt:420` and annexation/reform examples in `events/05_china.txt:538,686`. Use `annex_country = { target = CYP transfer_troops = yes }` only for full annexation. The docs excerpt describes the effect very tersely and does not prove peacetime asset, equipment, or country-variable accounting; fixture the exact effect in game.
- `transfer_state = <state id>` is documented in country scope as setting state owner and controller (`effects_documentation.md:8323-8328`). For a negotiated southern union, a Greek-country effect may transfer state 145. `transfer_state_to = GRE` is the corresponding state-scope form (`:7743-7754`). Do not call both forms for the same state.
- `add_state_core = <state id>` and `remove_state_core = <state id>` are documented country-scope effects (`:2191-2198`, `:6251-6258`). Adding a core grants core status immediately; it is not a gradual integration mechanic. `transfer_state` does not document any core change. Do not add Greek cores as part of the territory transaction. If eventual integration is a separate focus, make its cost, delay, political requirements and core change explicit, and separately decide the fate of existing Cypriot cores.

## Map and territory consequences

The 1970 history overrides state 146's base `NCY` owner and gives both state 145 and state 146 to CYP. State 145 contains province 11984 (Nicosia) and one oil unit (`history/states/145-Cyprus.txt:1-53`). State 146 contains province 7193 (Famagusta); its base owner is NCY, but its 1970 owner and controller are CYP (`history/states/146-Northern Cyprus.txt:1-52`). These are the only two CYP states in the audited 1970 island setup.

This makes the two proposed territorial outcomes mechanically distinguishable:

- **Full Enosis:** annex CYP, which transfers the whole CYP tag and its then-owned states. The `transfer_troops = yes` clause is the native option to carry existing Cyprus-owned formations across; it is essential to avoid replacing or duplicating previously accepted Greek reinforcements. Verify its peacetime result and each formation in an engine fixture. Do not create another division package during annexation.
- **Negotiated southern union:** transfer state 145 to GRE and leave CYP alive with state 146. At current map granularity, this is one state/one province, not a detailed municipal or ethnic partition. State 145 includes its existing infrastructure, buildings, manpower and oil field; transfer the state once and do not grant duplicate buildings, resources, slots or population. The core setup currently gives CYP and NCY cores on both states; `transfer_state` alone does not resolve those claims. The design must state whether the old claims remain, and must not silently grant GRE full cores.

For the southern-union transaction, ensure Cyprus formations are already in the retained CYP state before transferring state 145, or define a tested disposition for units stationed there. The state transfer changes state owner/controller; it is not a documented unit-transfer effect. Existing Greek-supplied units must not be recreated or handed over a second time.

## Consent and Turkish warning window

Use distinct Greek focus choices for full Enosis and negotiated southern union. The recipient decision must be delivered to CYP for real assent; it must recheck the ruling Cypriot authority, independence/existence, the selected territorial outcome and all final guards when accepted. Do not treat the Turkish government's assent as a substitute for either Greek-Cypriot or Turkish-Cypriot communal assent already represented by separate CYP receipts.

For the negotiated southern union, collect actual recipient-country consent from CYP, TUR and ENG before committing state 145. Treat Greece plus those three countries as a four-party compact: all six country pairs should be at peace and free of applicable embargo/sanction conditions at offer and final execution. If any party refuses or a guard changes, no state, core, troop, cash or recurring-spirit effects should be applied.

The current Turkish army chain cannot be reused as a fresh Enosis warning window. `COLDWAR_CYP_R2_start_army_crisis` is barred by permanent `COLDWAR_CYP_R2_army_crisis_started` / `..._closed` flags (`common/scripted_effects/COLDWAR_CYP_R2_crisis.txt:40-52`); the 30/60/180-day outcome is one instance (`events/COLDWAR_CYP_R2_crisis.txt:442-476`), and the actual intervention is barred once `COLDWAR_CYP_R2_intervention_receipt_used` is set (`scripted_effects/...crisis.txt:407-421`). Do not clear these receipts or reopen the old events. A genuinely renewed opportunity needs its own single-use Enosis-window flags, event IDs, timed outcomes and intervention receipt. The Turkish response must resolve before transfer; if Turkey takes the intervention option, invalidate the pending territorial commitment and leave the countries in the real war path.

Keep the proposed Greek coup-route outcome conditional on the actual CYP coup government and a completed, accepted CYP territorial choice. Execute only after the new Turkish window has closed without intervention and after final relationship checks. At execution, explicitly require no active GRE-TUR or CYP-TUR war (and preferably no active war involving any transfer participant), no Turkish intervention spirit/expense, and no unresolved coup, intervention or treaty event. This prevents annexation from deleting the target during war and turning the missing-Cyprus cleanup into a substitute for peace.

## Existing CYP-R2 lifecycle edges

- Direct Greek entry snapshots prior NATO membership and leaves NATO before joining the CYP-side war (`common/scripted_effects/COLDWAR_CYP_R2_crisis.txt:361-401`). The return helper requires the prior-member and separated receipts and native NATO eligibility (`:707-729`). Crisis reconciliation returns GRE/TUR after the GRE-TUR war has ended and, while CYP exists, after the CYP-TUR war has ended (`:644-666`). If CYP is absent, the code treats the CYP-TUR pair as cleared. Therefore full annexation must never happen during either related war; an annihilated CYP cannot stand in for a Turkish peace.
- `COLDWAR_CYP_R2_crisis_reconcile` also ends Turkey's Cyprus intervention expense and removes its intervention spirit if CYP no longer exists (`:585-603`). It recalls Greek volunteers only while CYP still exists (`:594-627`). Ensure volunteers are recalled before a full annex, and do not annex while a volunteer deployment is still present. Keep direct-entry war records and NATO separation alive until actual GRE-TUR peace; an Enosis reward or the 180-day military buff ending must not restore NATO early.
- The CYP-R2 `on_annex` hook calls `COLDWAR_CYP_R2_relationship_changed` (`common/on_actions/zzzzzz_COLDWAR_CYP_R2_on_actions.txt:11-17`). When CYP is gone, `common/scripted_effects/COLDWAR_CYP_R2_wiring.txt:20-40` invokes missing-Cyprus cleanup and crisis reconciliation; a USA monthly fallback repeats cleanup if necessary (`on_actions:7-9`). This already removes the active partner spirits for current Greek, Turkish, British, EEC and other CYP-R2 bilateral deals. Have the annex transaction invoke cleanup after annexation if the hook executes before target deletion, and verify it is idempotent. The fallback can otherwise leave state stale until the next monthly pass.
- The missing-Cyprus cleanup does not remove `COLDWAR_CYP_R2_idea_1960_treaty_of_guarantee` from GRE, TUR or ENG, although setup grants it to all three (`common/scripted_effects/COLDWAR_CYP_R2_core.txt:3494-3497`; idea definition `common/ideas/COLDWAR_CYP_R2_core.txt:69-75`). It is currently an empty-modifier historical marker, but Enosis should explicitly retain it as history or remove it as an ended treaty; do not leave this accidental. Check any active CYP program idea/receipt that might be copied to GRE by annexation.
- Independent-country annexation has no audited MD money transfer callback. The MD `on_subject_annexed` example explicitly adds subject treasury, debt and international investments to its overlord (`common/on_actions/01_tfv_on_actions.txt:37-70`), but CYP is independent, so do not assume that handler applies. The design must choose and execute exactly one accounting policy for CYP's treasury, debt and investments: transfer them once to GRE using MD variables, or explicitly extinguish/settle them in the agreement. State transfer carries no documented treasury transaction. GDP and state assets should follow their actual state ownership and MD recalculation; do not add a second GDP-based cash or resource reward as if they were newly created.

## Minimal transaction contracts

**Full Enosis:** CYP accepts the exact full-cession proposal; any required communal assents are distinct and present; fresh Turkish warning window resolves without intervention; all participants are at peace and Cypress remains independent before commit; volunteers are recalled; financial disposition is explicit. Apply `annex_country` once with `transfer_troops = yes`, record an irreversible receipt, remove or preserve the Treaty of Guarantee spirit deliberately, and run post-annex crisis/agreement cleanup. Do not add cores or spawn reinforcements. Verify states, buildings, resources, troops, treasury/debt/investments, tag deletion, NATO flags and remaining event flags in an engine fixture.

**Southern union:** CYP, TUR and ENG each accept the precise state-145 settlement; both communal assents remain separately valid; all six pairs remain eligible; no unresolved Turkish window or related war exists. Revalidate CYP ownership/controller of state 145, transfer it exactly once to GRE, and leave state 146 owned/controlled by CYP. Do not add a GRE core or duplicate any state assets. Define which CYP/NCY cores remain and how units located in state 145 are handled. Keep CYP-R2 paired agreements while their documented conditions remain true, unless the settlement explicitly terminates a named agreement; unlike full annex, Cyprus continues to exist.

Both outcomes are one-off territorial transactions, not standing bilateral spirits. They must be mutually exclusive and receipt-protected; refusing, timing out or failing a final recheck leaves land, troops, cash and Treaty status unchanged. A later focus may develop integration, but cannot repeat the territorial transfer.

## Latest concept build review

The current build resolves the earlier map and sovereignty concerns at the data level. Full Enosis requires CYP to own and control exactly states 145 and 146; the Southern route requires CYP to own/control only 145, with state 146 already owned and controlled by TUR or NCY. Both outcomes end the remaining CYP tag with `annex_country = { target = CYP transfer_troops = yes }`; the second route does not leave a CYP rump in the north or create new northern ownership. Separate Greek/Cypriot assent, actual TUR/ENG signatures, conditional NCY signature if NCY owns 146, six-pair sanction/peace checks, and separate communal safeguards are represented. The Turkish 30-day challenge starts a distinct war episode and says not to reset earlier army-crisis receipts or renew used 180-day buffs. The integration focus delays coring until 730 days, 70 compliance, peace and a rights/representation charter. Treaty-marker and post-annex cleanup, existing force transfer, interim costs and ledger succession are now explicit contracts.

Remaining concrete items for this concept build:

1. **The standalone preview drops new effect types.** `tools/greece_1970_rework_concept/preview.html:95-110` renders focus and offer effects through `effect(e)`, but has no cases for `political_power`, `annexation`, `country_cession`, `ledger_succession`, `opinion` or `union_integration`. Unknown types return an empty string. `agreement()` iterates side effects at `:111-115`, and the focus inspector calls the same renderer. Thus the current preview does not show either country's territorial outcome, the one-time PP charge, ledger transfer, recipient opinions or the later integration rewards, even though `build.py` emits those into the concept catalogue. Add renderer cases before calling the two-sided preview complete. Also provide the promised non-executing live snapshot for CYP treasury/debt/bond totals and actual forces; the current HTML has no dynamic fields for those values.
2. **The challenged full offer has no structured one-time resume lifecycle.** `enosis_full` is a 90-day pending offer. Its prose says a Turkish challenge pauses the proposal, war may last until a later peace, and the same proposal can resume once after renewed assent (`concept.json`, offer `enosis_full`, `turkish_window.resume`). The data has the final `..._committed` receipt and the warning-used receipt, but no pause receipt, resume-count/receipt, renewed offer ID or pending-period rule after peace. A long war can outlive the 90-day offer, while treating the CYP acceptance as reusable would violate the required fresh assent. Specify an at-most-once resume event and fresh CYP ratification after real peace, with explicit timeout/expiry and the original economic quote or a re-quote rule. Preserve the distinct `CYP_R2` once-only receipts.
3. **Recheck Cyprus's independence.** Both offers require Cypress's agreement and exact owned-state sets, but neither `territory` guard nor focus requirements explicitly says `CYP is_subject = no`. Add that at offer, acceptance and final annex. This prevents a nominal event choice by a non-sovereign subject from being treated as free consent.
4. **Name the MD bond mappings in ledger succession.** The contract now correctly calls for moving assets/liabilities and avoiding double transfers. MD's money model also stores bilateral bond positions as `given_bonds@TAG`, recalculates the aggregate `imp_total_bonds_held/owed`, and uses the aggregate in weekly investment calculations (`common/scripted_effects/imp_money_transfer_scripted_effects.txt:31-43`; `common/scripted_effects/00_money_system.txt:4662-4682`). The transfer contract should explicitly move both Cypress's holdings and each creditor's Cypress-issued position to GRE, clear the old `@CYP` entries, recalculate held/owed totals and refresh dirty money state. Merely adding scalar `treasury`, `debt` and `int_investments` would leave stale bond balances under the vanished CYP tag.

These are concept/preview gaps only. No runtime integration has been reviewed or changed here.

## Addendum: latest transaction and preview pass

The latest build resolves the four findings above in the design data and static preview renderer:

- The renderer now handles `political_power`, `annexation`, `country_cession`, `ledger_succession`, `opinion` and `union_integration`. The HTML catalog shows the proposed formulas and effect bundles.
- Full Enosis now has distinct `war_paused` and `resume_used` receipts, a one-resumption maximum, a fresh 90-day ratification window, renewed GRE/CYP approval, re-quoted balances, and expiry guarded by the matching non-paused offer instance. This preserves prior one-use CYP-R2 receipts.
- Both offers require CYP to exist and be independent at offer, acceptance, renewed ratification and handover. The exact set-of-states guards remain.
- The ledger contract now explicitly covers both directions of `given_bonds@TAG`, internal GRE-CYP netting, clearing old CYP mappings, recalculating held/owed totals, migrating investments and marking MD money state dirty.

Dynamic account and force values are still **not live in the external concept preview**. Its `live_preview_fields.implementation_boundary` correctly says the browser view shows formulas only, not connected game values. The eventual native, non-executing preview and the transaction's real ledger/force conservation still require implementation and an engine check; do not report those values or conservation as verified by this design-data pass.

The transaction-order finding is resolved in the current build. The Greek-side effect list now places ledger succession before annexation, and both offers carry an explicit `commit_order`: validate, snapshot, charge, migrate ledgers and bond positions while CYP exists, annex with existing troops, verify and record success, then clean up and refresh. The rollback policy is also explicit. Keep the native engine fixture as the remaining proof of execution order, ledger conservation and unit transfer.

One new guard mismatch remains. The concept specifies `CYP_exact_party_trigger = nationalist_military_junta_are_in_power`, but the native definition at `common/scripted_triggers/01_political_triggers.txt:323-327` tests `ruling_party = 22` (Nat_Autocracy). CYP's coup installer sets `ruling_party = 20` and the `nationalist` outlook at `common/scripted_effects/COLDWAR_CYP_R2_core.txt:3430-3432`. Slot 20's existing native exact-party trigger is `nationalist_right_wing_populists_are_in_power` (`01_political_triggers.txt:309-314`). Use that native trigger with the `COLDWAR_CYP_R2_coup_government` flag; otherwise the intended coup government fails the annex offer's final party guard. This remains a concept-data correction, not a runtime change.
