IMPERIA COLD WAR: Israel V2 native budget integration

28 October 2026. `tools/israel_v2/runtime_money.py` is a pure, fresh-read integration emitter. The root compiler writes its return. It patches the existing `00_money_system.txt`, `00_budget_effects.txt`, `00_economic_system_utilities.txt` and the direct human automatic-debt consumer in `MD_on_actions.txt`, and returns one new `ISR2_money_triggers.txt`. Existing upstream notices and unrelated programmes are retained. Every custom section has an exact project marker and a reversible source receipt where an inline native statement must change.

Income and expense hooks reset a separate aggregate to zero, sum the four actual country-local `ISR2_core`, `ISR2_domestic`, `ISR2_territories` and `ISR2_bilateral` weekly contributions with `has_variable` guards, and enter the native additional-income/additional-expense consumer once. Core, domestic and territorial contributions require the actual original Israeli tag in the 1970 scenario. Bilateral contributions require that actual actor or one of the fixed recipient tags in the 1970 scenario. A civil-war clone cannot activate copied monetary variables or flags, including a clone with original Israeli identity. The expenses enter after the native inflation multiplication, because their accepted quotations are already actual weekly amounts. Only Israel calls `ISR2_refresh` at this point. That provider has no daily timer progression. Actual Soviet principal/interest settlements remain separate atomic transfers and are never included a second time in these streams.

Native interest is calculated normally, including the current native foreign-currency debt factor. At the end of `calculate_interest_rate`, the hook removes the protected outstanding principal's `principal * 0.00019 * interest_rate * debt_fx_factor` contribution, capped to the current debt-rate charge. This applies even while a loan is temporarily suspended. It does not change the contracted fixed Soviet interest or forgive unpaid principal.

Manual, AI and human automatic repayments clamp their requested cash payment to `max(0, debt - protected_principal)` before debiting cash. The AI full-clear shortcut is skipped only for this protected borrower, which instead uses its existing reserve-aware gradual branch. Its final ordinary remainder can still be paid, while its native near-zero cleanup cannot erase a tiny protected principal. Other countries preserve their existing full-clear behavior. The human automatic consumer requires its own small on_action patch because it directly subtracts debt and treasury accrual without using an economic utility helper.

Anonymous `modify_debt_effect` write-offs are capped to ordinary debt without refunding Treasury. Native collapse restructuring and interest recalculation preserve the outstanding principal floor. Real bilateral instalments and optional early repayment use the explicitly named `ISR2_bilateral_apply_principal_reduction` transaction, which briefly authorises that exact ledger reduction before clearing its bypass flag. No broad debt write-off can use that path implicitly.
