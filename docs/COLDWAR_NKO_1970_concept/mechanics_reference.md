# NKO 1970 concept mechanics reference

Audit target: current `mdcoldwar-main` checkout, with installed MD donor `2777392649`. This note records source-backed mechanics for a concept tree; it does not implement a tree. Source line anchors below are relative to the current target checkout and should be rechecked if the code changes.

## Political start and actual party slots

NKO loads `mdcw_1970_generic_focus` in the 1970 setup (`history/countries/NKO - North Korea.txt:5-42`). The historical government is `ruling_party = 4`, with Kim Il Sung as leader through 1994 (`:8-37`). The history block clears and seeds the 24 party-array slots; the relevant starting shares are #1 `.03`, #4 `.78`, #5 `.04`, #7 `.08`, #13 `.03`, #19 `.04`, and #22 `.03`. The separate registry in `localisation/english/mdcw_1970_party_registry_l_english.yml:7408-7479` confirms slot #4 is WPK, #5 is KDP, and #7 is Chondoist Chongu. These are extant party/subparty indices, not proposed new registry entries. Retain WPK #4 as the 1970 historical start; KDP and Chongu are already distinct selectable parties for a concept.

The ideology file groups `communist_state`, `Conservative`, `Autocracy`, `Vilayat_e_Faqih`, `Mod_Vilayat_e_Faqih`, and `anarchist_communism` under the communist outlook (`common/ideologies/00_ideologies.txt:57-80`). The 1970 outlook mapper groups indices 4-9 into emerging communism (`common/scripted_effects/00_MD_politicsview_scripted_effects.txt:180-193`). Thus slots 5 and 7 are distinct intrabloc government paths while retaining the communist outlook. The registry labels are accurate names for the 1970 UI, but rewards and eligibility should use the actual `ruling_party` slot.

Native party-changing logic uses `ruling_party` as the current array index. `change_ruling_party_effect` is in `common/scripted_effects/00_leader_setup_scripted_effects.txt:1985-2065`; the base outlook and party index are reconciled through `update_set_politics` (`:120-264`) and party helper effects in `common/scripted_effects/00_MD_politicsview_scripted_effects.txt:255-330, 491-500`. A native focus can gate on `check_variable = { ruling_party = 5 }` or `= 7`; there is no reason to add a focus which merely unlocks a party already in office. For a governing-party-specific benefit, both focus availability and reward can use the same party gate where appropriate.

## Conditional programmes and cleanup

MD's existing 1970 programme pattern is a dynamic modifier with a native `enable` condition, e.g. `GEN_1970_cs_programme` in `common/dynamic_modifiers/mdcw_1970_generic_party_programmes.txt:147-165`. Soviet 1970 programme modifiers provide further party-conditional examples in `common/dynamic_modifiers/COLDWAR_SOV_1970_dynamic_modifiers.txt:183+`. NKO's own `NKO_hermit_kingdom` idea uses ruling-party allow/cancel logic (`common/ideas/north_korea.txt:54+`), but `cancel` removes the idea; it does not itself grant it back when the party returns.

For the proposed party paths, a conditional dynamic modifier is the cleanest native shape: `enable = { original_tag = NKO IMP_is_1970_scenario = yes check_variable = { ruling_party = <slot> } }`. Persist each completed programme's variables/receipt flag; the conditional modifier then deactivates when the government changes and reactivates when it returns, without replaying the focus payout. Any persistent cross-party industrial effects should be separate from these party-bound modifiers. Static source confirms the condition and modifier shape; save/load reactivation timing should still be checked in a live game.

## Native reward shapes and verified caution against donor copying

The installed MD donor's NKO tree (`C:\Program Files (x86)\Steam\steamapps\workshop\content\394360\2777392649\common\national_focus\05_north_korea.txt`) includes dynamic spirit-variable bonuses, agriculture districts, infrastructure, and technology bonuses. Examples include `NKO_promote_songun` at lines 69-107 adding `.05` attack/defense through the donor's `arduous_march_modifiers` mapping; food/health focuses at lines 160-220 use donor monthly-population/stability/research variables and `flat_productivity_change_effect`; infrastructure development at lines 253-318 builds infrastructure or grants technology bonuses. These are useful thematic examples, not direct API contracts for this target: the 1970 NKO scenario loads its own generic tree, uses MD's custom money/productivity/energy/uranium systems, and target NKO currently does not define that donor's dynamic modifier mapping. If using a donor-style variable, define its provider in the target and trace its consumer.

A safe concept reward package for this small, low-GDP state can generally use one meaningful persistent institution/output benefit plus an explicit 1-6 billion one-time project cost when a focus represents a major national programme. Values should be scaled to player economy and source capacity rather than copied from superpowers. For a recurring institutional choice, prefer a modest native percentage share of a relevant budget with a weekly MD-unit tooltip if the budget reader exists; otherwise it needs a new weekly expense integration. Benefits can be permanent where cross-government infrastructure is meant to endure, while leadership programmes should remain party-conditioned. A drawback is appropriate when it expresses a real financing or capacity trade-off, but it need not appear on every focus.

## New helpers or integration needed for a concept

- A custom NKO party dynamic modifier per programme is new content, but its conditional activation can use MD's built-in dynamic modifier `enable` predicate and existing `ruling_party` variable. Persistent reward flags/variables prevent focus replay from duplicating an outcome.
- Existing generic `mdcw_cw_add_weekly_expenses` is not a free arbitrary expense API: it only aggregates known CW cost variables/ideas; adding a new NKO project fee requires wiring its variable into the weekly expense aggregate.
- Existing Pyongsan deposit, paid uranium mine and nuclear project systems already cover surveying/development. The tree should call these hooks or unlock the extant investment decision path; no new production hook is needed.
- Directly granting party popularity, changing `ruling_party`, making a new ideology, or replacing the 1970 history block is not necessary for the requested KDP/Chondoist branches and would interfere with the existing political model.

Static checks establish the source declarations and formula flow. Tooltip rendering, dynamic modifier refresh timing, expense posting in an active save, and treasury affordability should be confirmed in-game after implementation.
