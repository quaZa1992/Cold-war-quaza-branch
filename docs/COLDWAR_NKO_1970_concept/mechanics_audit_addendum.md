# NKO 1970 concept mechanics audit addendum

This addendum reviews the regenerated `COLDWAR_NKO_1970_design.json` after the earlier corrections. The concept is now **source-backed, with new country adapters still unimplemented**. The JSON validator reports 167 nodes and no graph/layout errors, but it explicitly has `engine_tested: false`; static source review cannot establish that a future implementation loads, renders, or behaves correctly in game.

## Corrections confirmed in the regenerated concept

- Mobile-army fuel use now uses `army_fuel_consumption_factor`, which is present in native country ideas (for example `common/ideas/05_france.txt:1014`). The population heating/input modifier remains separately identified as `non_electric_fuel_consumption_modifier`; MD consumes it in `common/scripted_effects/imp_oil_prices_scripted_effects.txt:113`.
- `interest_rate_multiplier_modifier` is now labelled in percentage points, consistent with the native interest-rate calculation in `common/scripted_effects/00_money_system.txt:2560-2590`. `trade_opinion_factor` is described as trade opinion rather than as a trade-volume or agreement modifier.
- The western credit outline is arithmetically consistent at the concept level: 7.5 billion of principal funds a 7.5 billion industrial project, leaving no net project cash; its later repayment is represented separately with no additional focus price. The NPT offer’s 8% nuclear-generation benefit is conditional on both the recorded agreement and valid safeguards.
- Offers now enumerate who pays and who receives each outcome. Their design includes pending/accepted receipts, one-time execution, expiry, and bilateral validity checks. The confederation and NPT rewards also name the two-sided receipt or safeguards conditions.
- Building records now name explicit candidate state IDs and full project prices. These are useful adapter inputs, not proof that a state has a free slot at execution time; the runtime must still verify current ownership, control, and capacity.

## Remaining implementation contracts

**The 1970 starting-spirit baseline remains unverified.** The 1970 NKO history block sets `ruling_party = 4` and loads `mdcw_1970_generic_focus` (`history/countries/NKO - North Korea.txt:5-57`), but does not add national ideas there. The `add_ideas` block at line 898 is under the later `2000.1.1` history block, so its ideas must not be treated as active in 1970. Definitions for `NKO_hermit_kingdom`, `NKO_planned_economy`, `NKO_closed_nation`, and other NKO spirits exist in `common/ideas/north_korea.txt:4-110`, but definition alone does not prove 1970 assignment. The concept’s six `starting_spirits` are proposals, not verified loaded spirits. Before implementation, inspect 1970 startup on_actions and generic setup effects for any assigned idea or active dynamic modifier, then state whether each proposed spirit replaces or stacks with that verified baseline. The generic tree load and ruling-party setup are confirmed; the effective starting modifier baseline is not.

**Focus-money and financed-project execution still needs one explicit accounting contract.** The JSON has a nonzero `money` field on 67 of 167 focuses; these figures need one runtime interpretation and one charge point. The native `modify_treasury_effect` adds `treasury_change` to the treasury, while `modify_debt_effect` adds `debt_change` to debt (`common/scripted_effects/00_budget_effects.txt:1482-1504`). The native weekly `automated_debt_taker` handles a negative treasury by borrowing enough to restore a positive balance, with its documented cushion and 1% fee (`common/scripted_effects/00_economic_system_utilities.txt:25-40`); it is invoked after weekly treasury accrual in `common/on_actions/MD_on_actions.txt:166-170`. Ordinary project charges therefore can use the treasury debit and the existing weekly borrowing policy; no focus affordability gate or separate self-loan adapter is required. For western credit, acceptance should explicitly add 7.5 to debt, credit 7.5 to treasury, and debit 7.5 for the project, leaving net project cash at zero. Repayment should be capped by the recorded outstanding principal and available treasury, then debit treasury and reduce debt by the same amount. The current `extra` records principal, project price, and repayment amount, but the generated offer/loan helper still needs to implement these ledger operations exactly once.

**“Full project price” and generic focus `money` must not charge the same building twice.** The concept explicitly says there is no second native purchase fee for focus-funded buildings, but that guarantee depends on the new building adapter. Keep the price visible once, debit it once, and make recipient-funded offers transfer cash only on acceptance. For weekly programmes, use native percentage-of-budget modifiers where those are the intended ongoing effect; a flat weekly fee would require an additional expense-rate integration, not a one-time `money` charge.

**Party-owned spirit reactivation requires an implemented lifecycle check.** Party focuses carry slot and scenario guards in `runtime_guards`, but a completed focus will not replay when its party returns. The new modifier layer therefore needs a reconciliation path that removes or disables the outgoing party’s effects and restores already-earned effects when the same slot regains power. The existing generic dynamic-modifier pattern demonstrates outlook-based `enable` predicates (`common/dynamic_modifiers/mdcw_1970_generic_party_programmes.txt:147-165`); it does not by itself certify the new NKO slot checks, one-time earned flags, or reactivation behavior. The existing `NKO_hermit_kingdom` has a native slot-4 cancellation condition, but the rest of the loaded ideas are not uniformly party-bound.

**Acceptance and state-placement are still helper work, not native focus effects.** The offer outcomes are precise enough to implement, but event dispatch, pending receipts on both tags, expiry, duplicate suppression, recipient payment, safeguards invalidation, and owned/controlled state selection must all be implemented and tested. Likewise, `state_ids` narrows candidates but the state selector must re-check state existence, current ownership/control, and free per-type building capacity when the effect runs. Offer refusal or expiry must not transfer funds or grant either party’s reward.

**Nuclear and mineral promises depend on existing gates remaining in force.** The NPT offer’s conditional modifier must be removed or become inactive as soon as the safeguards receipt is invalidated; it must not unlock a reactor, uranium, a special project, or a weapon directly. Preserve the existing project and paid uranium-investment requirements. The NKO 1970 state history itself resets Pyongyang’s nuclear reactor to zero (`history/states/602-Pyongyang.txt:64-73`), so any project/readiness promise should remain a modifier or access condition rather than an unpriced starting facility.

## Status

Source-backed concept; new adapters remain unimplemented. No runtime/parser/game validation is claimed.
