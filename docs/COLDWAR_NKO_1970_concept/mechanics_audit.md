# Independent mechanics audit — NKO 1970 concept

Scope: `COLDWAR_NKO_1970_design.json` (167 nodes) and `build_concept.py`. This is a concept audit only; I did not edit the canonical design. Static source tracing verifies definitions and script flows, not final HOI4 parsing or tooltip behavior.

## Corrections that should be made before the concept is frozen

1. **Reconcile Western Credit’s cash and debt effects.** The native Treasury API is `set_temp_variable = { treasury_change = -X }` followed by `modify_treasury_effect = yes` (`common/scripted_effects/00_budget_effects.txt:1487-1494`). The debt API is a distinct `debt_change` followed by `modify_debt_effect = yes` (`:1497-1504`); it clamps debt at zero and does not change Treasury. A loan of 3 billion must explicitly add both +3 Treasury and +3 debt, then spend the borrowed cash on the plant. If that plant purchase spends 3 billion, the net cash change at the focus should be zero and principal should rise by 3. At `credit_reckoning`, the `money=3` Treasury cost correctly represents the cash paid to reduce principal by 3 only if `repay_loan` changes debt alone. If that adapter also charges Treasury, remove the separate `money=3` field. The `take_manual_debt_effect` helper is valid but has separate rate/GDP/IMF gates; it does not replace the simpler pair of native delta APIs when the design promises exact cash and principal amounts.

2. **Fix the interest-rate label and magnitude interpretation.** `interest_rate_multiplier_modifier` is added as a raw number to `pre_clamp_interest_rate`, which is itself in interest-rate percentage points, before the 0.8–50 clamp (`common/scripted_effects/00_money_system.txt:2560-2590`). Thus `+0.12` is **+0.12 percentage points**, not +12% of the current rate. Change the concept label from “Interest rate multiplier” to “Interest rate” or show “Borrowing rate +0.12 percentage points.”

3. **Fix the fuel modifier’s context and cost.** `non_electric_fuel_consumption_modifier` is real, but it multiplies population non-electric fuel consumption by `1 + modifier` (`common/scripted_effects/!_energy_effects.txt:620-637`). The oil-dependency calculation also uses it in the population share (`common/scripted_effects/imp_oil_prices_scripted_effects.txt:103-122`). Therefore mobile-army `+0.08` raises household/non-electric fuel demand by 8% and increases the oil-dependency input; it does not represent vehicle fuel consumption. Rename the label to “Population non-electric fuel demand” and decide whether the mobile-army focus should carry that civilian energy penalty. The cleanest military-specific existing choices in this design are equipment/personnel cost and supply consumption; do not invent an army-fuel key.

4. **Use “Trade opinion,” not “Trade deal opinion.”** `trade_opinion_factor` is a native opinion modifier. The design uses it at multiple nodes as a stand-in for an economic agreement or improved trade access, which it does not itself create. Rename the `STATS['trade']` label and all remedies/tooltips to “Trade opinion factor” or equivalent. Signed agreements, physical trade, and a foreign payment need their own explicit accepted-event effects.

5. **Encode government and agreement gates as runtime requirements.** The JSON carries `slot` metadata and prose `gate`, but it has no executable `available`/completion guard field. For every focus in groups with slots 5, 7, 13, 22, 2, 3, and 14, both availability and reward must check the matching `ruling_party` index. Keep WPK start at slot 4. For bilateral acceptance, the offer flag must be stored on both parties, and every later reward that depends on it must check the signed flag in both availability and completion reward. Specifically: `moscow_signed` for Soviet placements; `beijing_signed` for border trade; `channel_signed` for Red Cross and confederation; `atomic_cooperation` for safeguards; `council_signed` for any joint consultative spirit; and `npt_bargain` plus a still-valid safeguards flag for the nuclear-generation benefit. The new agreement adapters should grant those flags only in the recipient’s accept option and clear/deny any pending, refused, invalid or duplicate offer without charging money. A prose note such as “requires the signed channel” is not a runtime gate.

6. **Party modifiers need an actual reactivation path.** Persisting a completed-focus receipt prevents repeat payouts, but does not itself restore a dynamic modifier removed when its `enable` trigger fails. The adapter must reconcile each earned party receipt on party changes (or a reliable periodic hook): re-add/ensure the modifier when the slot returns, remove/deactivate it while another party governs, and leave durable national infrastructure modifiers active. Verify save/load and government-change refresh in game. Do not assume `enable` automatically reattaches a modifier that the engine removed.

7. **Make all building regions executable and price them.** Each `building` reward uses real building IDs in the target, but its `region` is currently prose. Replace it in the eventual adapter with specific state ID(s) or a real state filter, then check ownership/controller, free shared slots, level cap, building-specific placement, and availability before completion. NKO has six North Korean states in the 1970 map: 601 Hamgyong, 602 Pyongyang, 603 Hwanghae, 1199 Kangwon, 1200 North Pyongan, 1201 Chagang. Relevant source files show existing factory/power/infrastructure placement (`history/states/601-Hamgyong.txt`, `602-Pyongyang.txt`, `603-Hwanghae.txt`, `1199-Kangwon.txt`, `1200-North Pyongan.txt`, `1201-Chagang.txt`). Candidate locations such as 602 for industrial capacity or 1201/1199 for highland generation need free-slot and geography checks. The target building file lists native project prices, e.g. industrial complex $7.50, arms factory $7.50, agriculture district $3.75, renewable energy infrastructure $8.50, radar $1.75, fossil powerplant $3.25 (`common/buildings/00_buildings.txt:5-19`). The concept’s `$1–4bn` `money` fields therefore need a clear adapter contract: say whether the focus price is the full cash cost, a subsidy plus queued construction, or an extra amount on top of the native build price. Do not silently instant-build a building and separately charge an unexplained Treasury amount.

8. **Keep nuclear research, civil power and bomb projects separate.** `CAT_nuclear_reactors` and `CAT_nuclear_weapons` are valid research categories, and `add_tech_bonus` with 0.5/0.35 and one use is a normal bonus, not a project or weapon. `sp_nuclear_energy` is only available when `COLDWAR_nuc_economy_allows` is true (Emerging/Developed; `common/scripted_triggers/COLDWAR_nuclear_power_triggers.txt:4-12`) and consumes 6 uranium (`common/special_projects/projects/nuclear_projects.txt:20-21,59-61`). The bomb project is a child of it and consumes 4 uranium (`:126-197`); warheads require the bomb parent, missile tech and other prerequisites/resources (`:220-235`). Keep all these gates. The weekly nuclear budget is applied only when those special projects are researched (bomb/warhead bases 0.15384/0.09615 billion per week, GDP/c and inflation scaled; `common/scripted_effects/COLDWAR_nuclear_development_budget.txt:6-35`, charged into defense spending by `00_money_system.txt:3315-3316`). A research-category bonus does not start a project or incur that project’s weekly fee. NKO’s 1970 Pyongyang state resets `nuclear_reactor = 0` (`history/states/602-Pyongyang.txt`), so `nuclear_energy_generation_modifier = +0.08` produces no current electricity until a real reactor, fuel and manpower fulfillment exist. The safeguards offer must be conditional on accepted terms; the current text correctly labels the inspection/violation contract as a new adapter, because no current NKO inspection covenant hook was traced.

## Special reward and action contracts

- **Research:** the two nuclear category bonus records are valid normal research bonuses, but need explicit exact `available`/reward guards and one-use tracking. Do not imply that they unlock a treaty, facility, reactor or special project. The strategic focus has both a 35% category bonus and a new programme-access adapter; display those separately.
- **Treasury/debt:** all `money` amounts need actual `treasury_change` + `modify_treasury_effect` behavior and an affordability/reward guard. Every debt record needs `debt_change` + `modify_debt_effect`, with a clearly paired cash movement when lending or repayment is promised. Do not let the same amount be charged via both the `money` field and an adapter that also changes cash.
- **Buildings:** building types exist. The `region` strings are design descriptions only. The final adapter must select a real state and account for ownership, state slots, level limits, construction cost and whether it queues or instant-builds. For power, use the existing fossil/renewable energy building systems, whose state energy source feeds the weekly energy calculation; do not promise a fixed output until the target state’s capacity multiplier and resulting `energy_gain` are calculated.
- **Bilateral offers:** each current `kind=offer` is design data only; the current description/flag/conditions do not implement the message or payout. Use a recipient-controlled reply event. On acceptance only, transfer the stated amount with Treasury adapters, add any accepted buildings/ideas/temporary benefits to the intended recipient, and mark both participants with an offer-specific signed flag. On refusal or invalid partner, no party should pay or receive a benefit. Check partner country existence, independence, peace, and any same-side conflict at both dispatch and acceptance. `set_improved_trade_agreement` is a real bilateral opinion/signature hook (`common/scripted_effects/00_economic_effects.txt:89-116`) but does not perform cash transfer or create the particular NKO offers.
- **Special actions:** Planning decisions, the safeguards covenant, nuclear project access, the strategic-programme agreement, and a KPA handover commitment are explicitly new adapters. The existing investment offer system (`common/scripted_effects/99_investment_scripted_effects.txt:91-164`) covers state-building/investment offers and is a useful recipient-consent pattern; it is not a generic implementation for inspection obligations or a political succession charter. `Controlled Joint Ventures` can use existing investment project primitives, but needs a specific NKO offer configuration and its foreign relationship/tax effects. Do not describe any of these as an already available generic API until the adapter exists.


The `STATS` lookup in `build_concept.py` also declares `fossil_pp_energy_generation_modifier`, `renewable_energy_gain_multiplier`, and `nuclear_energy_generation_modifier`; they are not used as node modifiers in the JSON. The NPT offer’s prose benefit is the one place that promises nuclear generation +8%, but the `nucpower` key is not attached to that reward. If retained, implement a mapped `nuclear_energy_generation_modifier` variable on a conditional NKO dynamic modifier (signed `npt_bargain` and safeguards-valid), and ensure an existing reactor/fuel/manning chain can benefit. The native energy consumer is `common/scripted_effects/!_energy_effects.txt:473-511`. Otherwise revise the prose so it does not promise the unused bonus.
