# IMPERIA COLD WAR

## NATO exit, war and return: source audit

Read-only audit of installed Millennium Dawn at `E:/SteamLibrary/steamapps/workshop/content/394360/2777392649` for the Cyprus 1970 proposal. This records source behavior, not an in-game validation. The relevant 1970 startup path includes GRE, TUR, ENG and USA as NATO candidate tags; their actual membership is indicated by the `NATO_member` idea.

## Native API and state

- Use the scripted effect `NATO_leave = yes` to leave NATO. In `common/scripted_effects/01_NATO_effects.txt:164-230`, it removes `NATO_member` and `NATO_Tech_Share`, transfers faction leadership when the departing country leads, leaves its faction, removes reciprocal NATO opinion modifiers and military access, applies the departure opinion, and emits the native departure news. The Greece tree uses this helper in `common/national_focus/05_greece.txt:7144` and `:10216`.
- Do not reproduce Turkey's old `TUR_leave_NATO` focus body (`common/national_focus/turkey.txt:11087-11100`) as a general helper. That branch removes the idea and tech sharing but uses a different opinion cleanup and does not show the full shared leave behavior.
- Use `NATO_join = yes` to restore a previously departed eligible member. The same file at `:62-129` restores mutual member opinion and military access, adds `NATO_member` and `NATO_Tech_Share`, then joins the current faction leader found in `global.nato_members`. It also removes MNNA status. It is a scripted direct join, not an acceptance event.
- `NATO_join_via_event = yes` at `:131-162` routes accession through `NATO.14` from USA when USA is a member and faction leader, otherwise from a current NATO faction leader. It represents new accession with an event, so it is not the matching path for an automatic return after a temporary, pre-authorized wartime exit.
- `NATO_member` is also the authoritative runtime marker used by the helpers. Its `on_add`/`on_remove` in `common/ideas/Factions.txt:5-22` updates `global.nato_members`; do not manually edit that array when using the helper. `NATO_currently_exists` in `common/scripted_triggers/00_NATO_scripted_triggers.txt:1-5` checks only that the array is nonempty, not that it has a living, active NATO faction leader.
- The array is seeded with GRE, TUR, ENG and USA for starts before 2000.1.2 by `common/scripted_effects/00_startup_effects.txt:688-707`; the later-start list also includes TUR, ENG and USA at `:709-737`. These are candidate tags, not proof that each still has membership. Filter by `has_idea = NATO_member` and validate a real current leader before a return call.

## Volunteer and direct-war paths

- MD defines `on_send_volunteers` with ROOT as sender and FROM as recipient in `common/on_actions/07_nsb_on_actions.txt:443-460`; the hook records the actual sender and recipient and applies diplomatic opinion changes. The native volunteer diplomatic action remains engine-controlled. Mod script cannot force a volunteer deployment or bypass the live action's eligibility rules.
- For a Greece-volunteer outcome, treat the engine's accepted deployment as the evidence. The trigger `has_volunteers_amount_from = { tag = GRE count > 0 }` is used in `common/achievements/MD_achievements.txt:951-954` and `common/scripted_triggers/00_diplo_action_valid_triggers.txt:90-94`. A focus offer, flag, or event firing is not evidence that Greece has volunteers in Cyprus.
- `can_send_volunteers = yes` is present in the five ideology rules in `common/ideologies/00_ideologies.txt` at lines 26, 88, 143, 207 and 265. This is necessary at the ideology-rule level but does not establish that the engine will allow a particular diplomatic action. Same-faction and other live volunteer restrictions are engine behavior and were not verified in a game session.
- The Article 5 block in `common/on_actions/MD_NATO_on_actions.txt:12-43` runs on declaration of war, with ROOT the aggressor and FROM the attacked country. For a non-NATO attacker against a NATO member, it calls active independent NATO members into the war against the aggressor. Thus a direct CYP attack on TUR while TUR still has `NATO_member` can bring in NATO. The safe sequence is to call `NATO_leave` for each country that is currently a member before declaring CYP-TUR war. The helper must run before the declaration, not in response after the war hook.
- GRE, TUR and CYP should be treated independently on entry: snapshot each Greek/Turkish prior NATO membership before exiting, call `NATO_leave` only for those that currently have `NATO_member`, then declare war. A country that was already outside NATO must not be added to a return list. If another faction relationship or war makes exit/re-entry incompatible, do not force a replacement faction.

## Pairwise end and safe restoration

- The installed on-action documentation lists `on_peaceconference_ended`, `on_war_relation_added`, `on_declare_war`, `on_war`, and capitulation hooks (`common/on_actions/_documentation.md:19-33`), but no `on_war_ended` entry was found in the installed on-action files. A native monthly hook is present in `common/on_actions/MD_on_actions.txt:675-683`. Peace-conference completion is not equivalent to the two relevant bilateral wars ending. Use a monthly fallback, with declaration/war-relation hooks only as checks that update pending state, rather than a global-peace requirement.
- Define the end condition explicitly as both `NOT = { has_war_with = TUR }` in GRE and `NOT = { has_war_with = CYP }` in TUR, and also verify the CYP-TUR war is over from both sides. This prevents restoration while the Greek-Turkish or Cyprus-Turkish conflict remains active, while allowing unrelated wars elsewhere to continue.
- Store the pre-exit NATO status for GRE and TUR separately, before either helper runs. Once the pairwise end condition passes, attempt return only for a country whose saved pre-exit state was NATO member. Never use a generic “all peace” test, never restore a country that had no prior NATO membership, and never add a prior member that has since joined a different faction or become a subject.
- Before each automatic `NATO_join`, verify that the country is alive, is not already a NATO member, remains eligible through `can_join_NATO`, is independent, is not at war with an active NATO member, and that `global.nato_members` contains a live NATO faction leader. These checks avoid calling the helper when its random leader search has no valid target or when the country's intervening diplomacy makes NATO re-entry invalid. If checks fail, retain the pending return state and retry on the monthly fallback; do not repeatedly call the join effect.
- `NATO_leave` can transfer faction leadership. `NATO_join` searches for the current leader, so do not hard-code USA or ENG as the returning faction anchor. Both begin with NATO membership in the 1970 country histories (`history/countries/USA - USA.txt:305`, `history/countries/ENG - United Kingdom.txt:1361`); runtime leadership must still be checked at return time.

## Scope and confidence

This audit inspected installed script and history files only. It did not launch HOI4 or test focus visibility, volunteer diplomacy restrictions, war declaration UI, faction joining, or timing of peace hooks. The Article 5 sequence and state restoration recommendations follow directly from the inspected helper and on-action code; compatibility with engine-only diplomacy rules remains unverified.
