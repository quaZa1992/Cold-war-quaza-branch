Standardize one mod file to MD conventions without changing behaviour.

File to standardize: $ARGUMENTS

Upstream MD does this with `tools/standardization/standardize.py`, which is **not in
this repository** (see `.claude/docs/coldwar-1970-context.md`). Apply the rules by hand
from `.agents/skills/hoi4-md-recon/references/md-code-stylization-guide.md`, including its
"Applying the guide in this 1970 fork" section, and the matching `.claude/docs/`
reference.

Steps:

1. Determine the file type from the path:
   - `common/national_focus/` or filename contains "focus" → focus
     (`focus-tree-reference.md`)
   - `events/` → event (`event-reference.md`)
   - `common/decisions/` → decision (`decision-reference.md`)
   - `common/ideas/` → idea (`idea-reference.md`)
   - `common/military_industrial_organization/organizations/` → MIO (`mio-reference.md`)
   - `common/technologies/` → technology
   If the type cannot be determined, ask the user to clarify.

2. Refuse and explain when:
   - the file header names a generator under `tools/` that exists (`# Generated by ...`):
     standardize the generator's output template instead, then rebuild;
   - the file is a large inherited MD file and the user did not ask for the whole file:
     offer to standardize only the blocks the current branch changes
     (`git diff origin/main...HEAD -- <file>`).

3. Apply, block by block, only what is mechanical and behaviour-preserving:
   - property order per the reference;
   - a `log = "[GetDateText]: [Root.GetName]: <kind> <id>"` first line in each
     effect block the reference requires, with the block's own id;
   - remove redundant defaults (`cancel_if_invalid = yes`, `continue_if_invalid = no`,
     `available_if_capitulated = no`) and empty trigger blocks;
   - tabs for indentation, one statement per line where the reference asks, UTF-8
     without BOM for `.txt`.
   Do not rename ids, change values, reorder focuses or reflow inherited code the
   request does not cover.

4. Check: diff the file against its previous state and confirm only layout, order,
   logging and redundant-default lines changed; run the static checker on it
   (`.claude/docs/validation-pipeline.md`).

5. Report what changed per block (logging added, properties reordered, defaults
   removed), and list issues noticed but not fixed because they would change behaviour.
