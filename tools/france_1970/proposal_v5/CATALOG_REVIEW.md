# Mechanics catalog audit

## Corrections to make before using this catalog for balance

- **`experience_gain_army` is not a percentage modifier.** The vanilla localisation key is `experience_gain_army_tt` and formats `$RIGHT|+=2$` (`.../Hearts of Iron IV/localisation/english/modifiers_l_english.yml:253`); the separately named `experience_gain_army_factor_tt` is the percent modifier (`:255`). This is a flat daily Army XP rate. MD overrides the first key to `+=%1` (`.../2777392649/localisation/english/MD_dm_modifiers_l_english.yml:86`), which conflicts with vanilla's unit format and should be called out as an MD display mismatch, not evidence of a percentage engine unit. Keep it distinct from the `army_experience = N` one-time XP effect, which grants a flat pool as the catalog correctly describes.
- **`intelligence_agency_defense` is a flat counter-intelligence value in vanilla's own presentation.** Vanilla uses `$RIGHT|+=2$` (`modifiers_l_english.yml:1449`), while MD overrides it to `$RIGHT|+=%1$` (`MD_dm_modifiers_l_english.yml:353`). The catalog's current “fractional engine modifier, displayed as percent” follows the MD override but obscures that discrepancy. Describe it as counter-intelligence points, and note MD's percent display requires in-game validation before communicating 0.075 as “7.5%.”
- **`land_reinforce_rate` is an additive chance value.** Vanilla describes it as “Chance per hour that units in reserve are able to actively join the fight” (`modifiers_l_english.yml:746`) and displays it with percent formatting (`:747`). A value of 0.05 therefore represents +5 percentage points to that chance, not a 5% multiplicative increase to an existing rate. “Fractional engine modifier” is ambiguous; use “additive percentage points (reinforcement chance per hour).”
- **Several calibration signs conflict with their declared beneficial direction.** Examples include `land_doctrine_cost_factor = -0.1` with direction `lower` (a negative cost factor is beneficial); `trade_opinion_factor = -0.15`, `local_resources_factor = -0.025`, `tax_gain_multiplier_modifier = -0.05`, `imp_sanction_resistance = -0.06`, and `productivity_growth_modifier = -0.15` with direction `higher`. Check the registered formula and actual consumer before stating direction; in several cases the example may be a penalty rather than a beneficial calibration. Do not conflate “direction that improves the metric” with the sign of an example modifier.
- **Very small values may disappear in rounded UI paths.** Before adopting small modifiers, inspect each actual idea/dynamic-modifier tooltip format and custom effect formatter. `%1` is normally one decimal percentage place after the engine converts a fractional value to percent, so 0.025 should display about 2.5%, not 0.0%; values around 0.0005 or smaller are the likely ones to round to 0.0%. The `experience_gain_army` vanilla `+=2` path instead shows a flat value to two decimals, while MD changed it to `%1`. The catalog does not record the display format for every custom modifier, so verify each actual tooltip rather than assuming all small values remain legible.

## Equipment and research mechanics

- `equipment_bonus` is a **modifier container with equipment-type subkeys**, not a universal free-standing bonus. Its semantics come from child fields such as `build_cost_ic`, `reliability`, or attack values and from the targeted type. The cited German idea at `common/ideas/German.txt:581` demonstrates `train_equipment`, `util_vehicle_type`, and `heavy_util_vehicle_type`; it does not establish that every type exists in every DLC configuration. Validate each proposed subtype in the loaded equipment database for the target DLC set. The shown `instant = yes` applies the idea modifier immediately; because it is housed in an idea it is retractable when that idea is removed. Keep distinct from `add_equipment_bonus`, which creates a named design bonus and is not made reversible merely by removing a spirit.
- `add_tech_bonus` is a native finite-use research bonus. Category eligibility and named technology targeting must be checked against the actual 1970 tech tree. DLC special projects are a separate eligibility path: ensure the intended project exists/is enabled for the scenario and its DLC, and do not infer access from ordinary category membership. The catalog's warning to use source-verified category membership and DLC project eligibility is sound; it should preserve the distinction between these two systems.

## Scope and limitations

This is a static audit of the catalog against the installed vanilla/MD localisation and script examples. Vanilla strings establish intended tooltip units, not the engine's hidden formula. In particular, MD's two tooltip overrides above conflict with vanilla formatting and need an in-game tooltip check before a user-facing percentage claim. Script examples establish that a value is used, not that it is balanced or positive in all contexts. The generic calibration recommendation to “calibrate below the full upstream national reform” is not an evidence-backed numeric cap; compare actual stacked modifiers by family and avoid treating it as a universal rule.
