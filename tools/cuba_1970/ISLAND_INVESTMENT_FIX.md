# IMPERIA COLD WAR — Cayo Blanco del Sur investment menu

State 1252's investment menu was hidden by its `state_inhospitable` category. Both the foreign-investment window (`common/scripted_guis/01_investment_scripted_gui.txt:60-68`) and the owned-state investment menu (`:525-533`) require the selected state not to have that category. Its category also defines zero local building slots (`common/state_category/state_inhospitable.txt:3-8`).

State 1252 now uses native `state_00` in [the state history](../../history/states/1252-Cayo%20Blanco%20del%20Sur.txt:7) and in [its canonical island builder](../cayo_blanco_del_sur/build.py:203). `state_00` is the native under-300,000-population category and supplies one local building slot (`common/state_category/state_00.txt:3-8`). The state keeps manpower 1, infrastructure 0, and no starting economic buildings or resources. Province 16537 remains assigned to Cuba strategic region 212 (`map/strategicregions/212-Cuba.txt:8`).

Kharg (State 1241) uses `state_01` with four local slots and infrastructure 1 (`history/states/1241-Kharg.txt:9-16,37`; `common/state_category/state_01.txt:3-8`). West Berlin (State 1251) uses the non-inhospitable `state_mdcw_berlin_sector` category with seven slots (`history/states/1251-West Berlin.txt:6`; `common/state_category/mdcw_berlin_sector.txt:3-7`). These comparison states do not need special GUI exceptions.

The AI investment filter separately excludes states below 50,000 population (`common/scripted_triggers/00_investment_scripted_triggers.txt:607-613`); this change does not alter that filter. No GUI-wide trigger, starting building, manpower, infrastructure, or resource was added.

Existing saves receive a narrow repair through `COLDWAR_CUB_repair_island_investment`, called by Cuba's daily update. It changes only State 1252 when the existing island flag is present and its category is still `state_inhospitable`. The state-scoped operation does not depend on its current owner, so a later DDR transfer remains supported. After restarting with the updated mod, the first daily update applies the repair. `set_state_category` is already used by the native `state_init_setup` effect (`common/scripted_effects/00_economic_effects.txt:12-80`). The native fixture checks the actual repair helper after deliberately restoring the old category; a real save/load and manual UI interaction remain outside that fixture's scope.
