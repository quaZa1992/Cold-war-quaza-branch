# IMPERIA COLD WAR — Failure scenarios to trace

Choose the rows relevant to the requested mechanic. They are scenarios to investigate, not claims that every omission is a bug.

| Boundary | Concrete question |
| --- | --- |
| Same-period execution | Can two human countries or co-op clients reach a global pass twice? Does the runtime receipt guard the final effect? |
| Delayed offer | Does the eventual option use the correct sender, recipient, committed terms and live eligibility? |
| Target lifetime | What happens after annexation, civil war, release, government change or loss of a named target? |
| Replay | Do repeated clicks, another event instance, restored spirits or a rehost repeat fees or assets? |
| Arithmetic | Are totals reset, constants defined in their actual file, indices bounded and denominators positive? |
| Idle display | Do hidden/closed views or AI countries still rebuild expensive player-only text? |
| Preview | Can a locked, unsigned or suspended agreement show both complete numeric outcomes without executing them? |
| Ownership | Are building slots and levels granted to the same real owned/controlled state with native capacity checked? |
| Authority | Does a recipient really choose, and can an AI path or GC fallback bypass that human choice? |
| Persistence | Are gameplay flags/arrays serialized, migrations one-time, and derived GUI state safely rebuilt? |

Upstream false-positive lists are leads, not blanket exemptions. A decision may use inherited base-game art; resolve it before calling it missing. A diagnostic about diplomatic GUI context needs a native reproduction before redesign. A permanent bad spirit may intentionally have no removal path. A missing reference in an incomplete fixture is unresolved.

When country identities differ, trace registered tags and cosmetic histories separately. The project used `SER` for 1970 Yugoslavia in the audited agreements. Preserve stable `_YUG_` receipts where required rather than mechanically renaming every matching string.
