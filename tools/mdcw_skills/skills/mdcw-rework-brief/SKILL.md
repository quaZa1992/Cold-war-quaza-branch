# IMPERIA COLD WAR — Country and mechanic design briefs

Read `AGENTS.md`. Resolve the supplied country, proposal, issue, mockups and requested design scope. Use the actual repository if the request references a tracker. A missing issue number is irrelevant when the user supplied the task itself.

Inventory existing relevant trees, ideas, decisions, party institutions, economic systems, diplomacy, characters and art. Verify each asset claimed as reusable. Research January 1970 history and credible institutional alternatives, with recorded sources. Distinguish facts, plausible alternate history and game-balance proposals.

For each substantial mechanic explain its purpose, real-world basis, actual starting state, affected systems, meaningful player choices, costs/trade-offs, progression and resolution. Show how interacting mechanics depend on one another. Ground a choice in the actual country's parties, religion and institutions instead of filling every MD outlook slot.

Keep normal design prose readable to an RP player. Put implementation pointers and reusable asset IDs in a short technical appendix when useful. Effect proposals still need concrete amounts and units where the assignment requires reviewable balance; political explanation does not replace numeric terms.

Use native MD presentation and comparable mechanical examples. Respect existing approvals and country-specific limits. Cuba's 120-focus limit and workforce constraint apply to Cuba, not every country. Do not impose a generic-tree minimum or a standard event quota.

Preserve the intent and relevant mockups of the original proposal, noting unavailable evidence. A concept render is a concept. A design brief implements nothing unless the user also requests implementation. If approval was explicitly reserved, provide a concrete proposal; otherwise do not invent a new confirmation loop. Updating a tracker body is a separate external action requiring existing authorization.
