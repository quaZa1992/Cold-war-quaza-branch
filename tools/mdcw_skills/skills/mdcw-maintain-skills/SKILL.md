# IMPERIA COLD WAR — Durable skill maintenance

Read `AGENTS.md` and the current `skill-creator` instructions when available. Identify the requested durable preference or demonstrated correction and its scope. User instructions take precedence over upstream recipes and existing skill advice.

Find the current owning skill or reference before adding a new rule. Distinguish reusable behavior from country-specific balance, one-time approvals, stale test counts and implementation details that the live code already explains. Do not generalize Cuba's limits, an individual game's test result or a single engine diagnostic into universal policy.

Use concise entrypoints with discriminating descriptions and load substantial domain references only as needed. Preserve existing useful material and invocation policy. Keep automatic discovery enabled for new skills unless the user requests otherwise. Do not copy Claude-specific model pins, tool permissions, agent fan-out or reporting rituals into Codex.

For an upstream update, pin the commit, inspect the actual sources and licence, document source-to-skill mapping and conflicts, then adapt for the installed MD version, 1970 history and current project standards. Do not execute downloaded helpers merely because a skill references them. Update capabilities only after verifying local tools and their supported flags.

Prepare and validate the concrete skill files in the project before installing outside the workspace. Preserve existing versions and compare expected hashes so another chat's edits are not overwritten. Keep project markers after skill frontmatter, valid YAML metadata and provenance. A skill marker does not claim ownership of its upstream material.

Apply already-requested updates without an invented confirmation stage. Request approval only for genuinely missing authority, not because upstream's update-claude recipe always does. Do not alter unrelated app settings, issue trackers or global configuration. Report installed skills, meaningful changes and any validation limits; freshly installed skills become available on the next turn.
