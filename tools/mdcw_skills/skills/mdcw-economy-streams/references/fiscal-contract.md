# IMPERIA COLD WAR — Fiscal integration boundaries

Treat the current economy as the authority for units and cadence. The upstream additional-income recipe supplies a useful four-part trace: calculation, display idea, English numeric text and activation. It does not establish this checkout's weekly conversion, payment ordering or agreement lifecycle.

For each stream record its source budget and unit, conversion, runtime weekly amount, payer, recipient, activation/suspension, display variable, accumulator and final treasury consumer. Read the actual source before selecting income versus expense signs. Preserve agreed values and distinguish calculation changes from balance proposals.

Check file-local `@` constants and fixed-point precision. The nuclear budget audit demonstrated that a missing local constant can survive a Python model which injects its own default. Models should consume actual source declarations and reject undeclared constants. Do not hide missing data behind a test-only default.

Recalculation must clear obsolete contributions before adding active ones. Repeated weekly passes must not compound a cached total, repeat a setup fee or mint assets. Check zero activity, changed controllers, blockade/war, parent membership and both parties' sanctions at the point the programme runs. Keep snapshot terms versus live dynamic prices explicit where the approved design distinguishes them.

For a building helper, inspect whether it already charges treasury and grants slots. Do not charge twice or assume a helper grants the project's extra slot for every level, including infrastructure and province forts. Keep payment and construction feasibility within the same one-time transaction.

Use real weekly numeric costs in runtime and player text. Native signed modifier previews and both countries' complete prospective terms remain visible before consent, but their rendering cannot execute effects. Inspect source, model, native weekly application and multiplayer/rehost separately.
