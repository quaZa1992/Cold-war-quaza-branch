# Approved SSR implementation coordination

The user approved the complete equipment-cost revision on 25 October 2026 and explicitly requested automatic spirit replacement on independence. `approved_design.json` is the immutable approved source snapshot. The concept source remains separate.

The implementation uses one universal focus tree, `COLDWAR_SSR_1970_focus`. Shared and specialisation focuses occur once. Country-specific regional and party modules use country-only visibility conditions. Party identity never hides a branch. Shared SSR content requires SSR status, without an ideology condition.

Shared Python API: `shared.data()`, `models()`, `nodes()`, `number()`, `write()` and `loc_text()`. Normalized nodes have `scope_tag`, `group_key`, and `receipt`. Receipt flags are `<canonical focus ID>_rewarded`. `models()` remaps all specialisation IDs to `COLDWAR_SSR_special_<role>_<step>`; country political/regional IDs remain as approved. All modules expose `generate()` and return the generated relative paths. Each module owns its own runtime and localisation files.

Root compiler owns focus declarations, one-time rewards, building site guards, the tree loader effect and economy integration. It emits `COLDWAR_SSR_reward_<focus key>` for common focuses and a country-prefixed key for country modules. Each successful guarded completion sets the normalized receipt once, pays GDP costs once, issues durable assets once, then calls `COLDWAR_SSR_reconcile = yes`. Reward guards use `COLDWAR_SSR_is_ssr` or `COLDWAR_SSR_is_independent`, the exact party trigger where applicable, geography and actual building eligibility. No default treasury gate is added to focuses.

Lifecycle module owns `COLDWAR_SSR_is_participant`, `COLDWAR_SSR_is_ssr`, `COLDWAR_SSR_is_independent`, `COLDWAR_SSR_reconcile`, starting problems and reforms, inherited transition liabilities and repair receipts, ordinary programme activation, party activation, nine specialisations and their independent variants, equipment bonuses and the cheap daily status watcher. It owns its on_actions file and calls `COLDWAR_SSR_load_tree = yes` at initialization. Rebuild only on a receipt, actual status/party change or migration; do not rescan all focuses for every country each day. A selected specialisation is one combined visible idea, using the finite reachable stage/choice combinations for its modifiers and equipment bonuses. Full and legacy versions cannot coexist. Durable assets are never issued by reconciliation.

Market module owns three once-only 730-day economic courses and finite sector settlement decisions, authority charters and their suspension. Root calls `COLDWAR_SSR_start_market_shock/gradual/directed = yes` for the corresponding course; the market module owns timed idea activation and the persistent restructuring spirit. `COLDWAR_SSR_market_reconcile = yes` is called by lifecycle reconciliation/daily cheap scheduler as needed. `COLDWAR_SSR_market_weekly_expense` is a weekly money variable, refreshed from current GDP. National receipts and deadlines survive party/status changes. The module may use current normalized political focus receipts to check charter authority.

Diplomacy module owns seven contract offer types, target selection, recipient acceptance/refusal decisions, full two-country numeric previews, bilateral status/sanction reconciliation, refusal retries and termination. Root calls `COLDWAR_SSR_offer_<contract> = yes`. Preview effects are `COLDWAR_SSR_preview_offer_<contract> = yes` and must show full prospective numeric outcomes even while currently locked. The diplomacy module owns `COLDWAR_SSR_diplomacy_reconcile = yes` and `COLDWAR_SSR_diplomacy_weekly_expense`, evaluated for recipients as well as SSR participants. It may provide availability triggers `COLDWAR_SSR_can_offer_<contract>`.

Root wires one weekly-cost effect into MD's existing additional-expenses calculation. It reads the lifecycle, market and diplomacy weekly variables exactly once. All setup prices and recurring budgets use approved GDP fractions. No new currency system or subject subsidy is introduced. Modules must report which callbacks and names they actually emit before integration.

All script files use UTF-8 without BOM. Only English localisation uses UTF-8 with BOM. Native numeric effect previews, exact party predicates, one extra shared slot before every building grant and no repeated transactions are mandatory. No module may overwrite another module's runtime or shared source files.
