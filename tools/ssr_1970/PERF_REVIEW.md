# SSR runtime workload review

Static call inventory of the new lifecycle, diplomacy and market modules plus their economy integration. This is an operation and fanout estimate from source, not a profiler trace or timing claim.

## Main recurring cost

`on_weekly` calls `ingame_update_setup` in the current country scope ([MD_on_actions.txt](../../common/on_actions/MD_on_actions.txt:4), [MD_on_actions.txt](../../common/on_actions/MD_on_actions.txt:39)). That setup reaches `calculate_additional_expense_rate` ([00_money_system.txt](../../common/scripted_effects/00_money_system.txt:267)), which now calls `COLDWAR_SSR_add_weekly_expenses` ([00_money_system.txt](../../common/scripted_effects/00_money_system.txt:4552)). The integration invokes lifecycle, market and diplomacy budget refreshes once per setup pass.

The diplomacy budget now resets `COLDWAR_SSR_diplomacy_weekly_expense` and its temporary fraction unconditionally, then runs reconciliation and aggregation only when the current country has `COLDWAR_SSR_dip_activity` ([generator](diplomacy.py), [emitted effect](../../common/scripted_effects/COLDWAR_SSR_diplomacy.txt)). Reconciliation has the same guard. Thus idle countries perform one activity-flag check and the zeroing writes, rather than the prior **399 reconciliation and 196 budget `if` blocks** each weekly setup. Active countries retain the full fixed 7-contract by 14-origin checks and pair validity tests, plus any extra `ingame_update_setup` invocation from an on-demand economy refresh or another caller.

Dispatch sets the activity flag on both the originating country and named recipient while a decision is pending. The flag is retained for accepted agreements even when war, embargo or sanctions suspend their spirits and expense; this lets the same weekly pass restore them when terms recover. Refusal and either-side termination call a bounded activity refresh across all outgoing and incoming pending/active receipts, clearing the fast-path flag only when that country has no remaining agreement state. Reconciliation now guards `add_ideas`/`remove_ideas` with `has_idea`, avoiding repeated native idea operations for active or idle recipients. Existing saves from an unreleased development build do not have the activity flag; no released-save migration is required for this feature.

## Other paths

- **Lifecycle daily check:** fourteen tag-specific daily callbacks run `COLDWAR_SSR_lifecycle_check_status`, market reconciliation and activity-guarded diplomacy reconciliation ([on_actions](../../common/on_actions/COLDWAR_SSR_lifecycle_on_actions.txt:26)). The lifecycle status effect has 11 `if` blocks, mostly participant, status, negotiated-state and cached party-slot comparisons. It calls the full lifecycle reconcile only on initialization, a newly recorded sovereignty transition, negotiated-state toggle, party-slot change or status-cache change. The daily hooks do not scan the world. Each active diplomacy origin additionally evaluates 399 inner `if` blocks and 98 `else_if` blocks; an idle origin exits the single outer activity guard. The weekly budget has 196 inner conditions and one activity guard.
- **Market daily check:** `COLDWAR_SSR_market_reconcile` is called for those same fourteen tags. It has 10 `if` blocks and begins with one pending-transaction resolver call ([effect](../../common/scripted_effects/COLDWAR_SSR_market.txt:1042)). The resolver has 25 `if` blocks, but its 24 method branches sit behind the pending-transaction and expired-timer guard. The only state iteration is in selected-state cleanup or successful liquidation after a pending transaction resolves; ordinary daily passes do not scan states.
- **Lifecycle rebuilds are large but event-driven:** a single `COLDWAR_SSR_rebuild_groups` call contains 1,215 generated receipt conditions across the 1,242 unique merged nodes and 182 dynamic groups. A `COLDWAR_SSR_rebuild_specialisation` call contains 315 generated conditions for nine roles and their reachable states. The startup callback initializes the fourteen roster tags individually, and each valid SSR initialization reconciles once. The combined static upper count is 21,420 conditional blocks across those fourteen rebuild pairs at startup, plus variable clears and dynamic-modifier operations. Root focus rewards also request reconciliation, as documented in [the integration contract](IMPLEMENTATION_CONTRACT.md:10). This work does not iterate world countries or states, but it is the main bounded startup and focus-completion workload if later native samples still show a concern.
- **Nested callbacks are guarded:** lifecycle reconciliation calls market and diplomacy reconciliation; neither calls lifecycle reconciliation. Market resolution can call market reconciliation once after clearing the pending flags, so its nested resolver immediately exits its pending guard. Diplomacy reconciliation notifies the saved recipient only after an actual origin-side idea mutation. Recipient aggregation does not notify back. If a recipient is itself an origin with another changing agreement, further nested checks are possible; each origin idea is changed before notification and its `has_idea` guard prevents repeating the same mutation in a cycle. Stable pairs cause no notifications. Diplomacy reconciliation does not call its budget refresh. Release and ruling-party callbacks are event-driven, not recurring.
- **Market weekly refresh is guarded:** it always clears one weekly variable, then only calculates 24 fee variables when the current country is independent and has started a market course. It does not call market reconciliation. Lifecycle weekly refresh likewise clears one variable and puts its receipt loops behind SSR or independent status checks. Market-course costs are owned by the market provider, not duplicated by the lifecycle provider.

## Measurement limits

The reported 424-second native startup attempt stopped during January 1 initialization; it is not a comparable runtime sample and does not isolate SSR work. The earlier 114-second engine probe used the pre-SSR source and a different 8-check probe. Neither result supports a before/after SSR timing estimate. No native profiler trace, multiplayer sample or controlled comparable run was available for this review.
