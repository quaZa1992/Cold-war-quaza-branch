# Market module review

Read-only review of the current market generator, emitted scripts, approved data and Python transaction model. The market files match the generator after accounting for the project-marker header emitted by `shared.write`; no market source or runtime files were changed.

## Findings

- **Pending settlements reserve the decision immediately.** All 24 decisions set a country-scoped `pending_<sector>_<method>` flag, a shared `pending_transaction` flag and the method's timed `pending_timer`. Visibility and availability block another settlement while that reservation exists. The resolver runs from market reconciliation and calls the method completion only after the timer flag expires. The participant daily callback invokes reconciliation, so party changes, status transitions and save/load do not rely on a one-shot focus callback. Sources: [market generator](tools/ssr_1970/market.py:260), [emitted decision](common/decisions/COLDWAR_SSR_market.txt:41), [daily hook](common/on_actions/COLDWAR_SSR_lifecycle_on_actions.txt:26).
- **Cancel and failed completion charge nothing.** Cancellation clears pending country flags and selected-state markers only. Completion validates sovereignty, pending method, unsettled lot, charter authority, affordability and, for liquidation, the selected-state criteria before any treasury change, building removal or receipt. Failure has no `else` transaction path; cleanup still clears the pending action. Tests cover cancel, lost sovereignty and invalid liquidation state. Sources: [completion and cancel generator](tools/ssr_1970/market.py:51), [emitted transaction](common/scripted_effects/COLDWAR_SSR_market.txt:175), [tests](tools/ssr_1970/tests/test_market.py:156).
- **Liquidation is state-specific, revalidated and not a free factory deletion.** The selected state must still be owned and controlled by ROOT, be ROOT's core, and have more than one civilian factory. Those checks precede payment and removal; success removes exactly one level. State flags are distinct per SSR tag, set on the targeted state and cleared after either success or failed/cancelled execution. This prevents one SSR's cleanup from erasing another SSR's selection flag. Sources: [selection and target guard](common/decisions/COLDWAR_SSR_market.txt:41), [execution guard and removal](common/scripted_effects/COLDWAR_SSR_market.txt:175), [model test](tools/ssr_1970/tests/test_market.py:187).
- **Costs and proceeds use current GDP fractions and native numeric previews.** Auction: fee 0.05% GDP, proceeds 0.15%; workers: fee 0.12%, proceeds 0.03%; liquidation: fee 0.03%, proceeds 0.08%; public conversion: fee 0.20%, no proceeds. Native `treasury_change` effect rows show signed currency amounts at decision selection. Completion recomputes both values from `gdp_total`, so settlement uses GDP at completion, which can differ from the preview if GDP changes during the wait. Availability's fee variables are refreshed by the weekly integration, so the button's affordability check can lag a GDP change until refresh; completion rechecks actual affordability and cannot overdraw. Sources: [transaction generator](tools/ssr_1970/market.py:51), [native preview](tools/ssr_1970/market.py:260), [weekly refresh integration](tools/ssr_1970/integration.py:34).
- **Deadlines are persistent calendar timers, not restarted on party/status changes.** Each course starts once with a 730-day country flag. Its window modifiers are suspended while the country is not independent and restored only while the original deadline remains; the deadline continues to elapse through party/status changes and save/load. Recurring charges use weekly GDP fractions as authored: gradual 0.005% per week and directed 0.015% per week; shock is zero. There is no extra division by 52. This matches the approved contract that deadlines survive party/status changes. Sources: [deadline and reconcile](common/scripted_effects/COLDWAR_SSR_market.txt:6), [contract](tools/ssr_1970/IMPLEMENTATION_CONTRACT.md:14), [expense refresh](tools/ssr_1970/market.py:143), [integration](tools/ssr_1970/integration.py:34).

## Limits

The Python harness models settlement and course behavior but does not emulate HOI4's exact timed-flag expiry tick, scope semantics or MP synchronization. The generated script ordering appears correct; in-engine confirmation of one-elapsed-timer execution, native tooltip rendering and save/reload timing remains with the parent runtime check.
