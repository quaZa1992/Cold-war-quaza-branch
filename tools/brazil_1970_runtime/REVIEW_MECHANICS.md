## Verified lowering references

- `gdp_total` is MD GDP in billions of internal dollars. Use it for script math; 1970 historical-dollar display variables are presentation conversions and are not the Treasury input. See `common/scripted_effects/00_money_system.txt` and `tools/france_1970_design/GDP_COST_REFERENCE.md`.
- Concept `treasury_gdp.percent` values are percentage points of GDP. A 0.65 percent charge lowers as `gdp_total * 0.65 / 100`; charge it once through `treasury_change` and `modify_treasury_effect`.
- Concept `weekly_gdp_expense.annual_gdp_percent` is an annual percentage appropriation. A 0.12 percent stream is `current gdp_total * 0.12 / 100 / 52`. Recalculate it in the native expense aggregation so it follows current GDP. It is a weekly MD rate, not an immediate Treasury debit.
- `MD_on_actions.txt` calls `ingame_update_setup` from `on_weekly`; the money system also calls it on demand. That setup calls `calculate_additional_income_rate` and `calculate_additional_expense_rate`. These aggregates reset their totals before rebuilding them. Keep custom stream aggregation idempotent and add exactly one integration call to each aggregate. Do not accumulate a second time from a separate weekly action.
- France integration appends its callbacks at the end of the native aggregation effects. In the expense effect, native inflation compensation is applied before the end (`00_money_system.txt:4588-4590`); append Brazil's current-GDP stream after that multiplier so the appropriation is not inflation-adjusted a second time.
- France 1970 is the direct integration precedent: `tools/france_1970_runtime/integration.py` inserts one stream aggregator call into each native aggregate. Paired transfer income is recorded under `additional_income_rate`; source expense is recorded under `additional_expenses_rate`.
- For a current-GDP BRA to PAR agreement, charge BRA's current GDP share divided by 100 and 52 in both source-expense and recipient-income scopes. Both use the exact same source quote; do not quote from PAR GDP, and do not use the France precedent's cached quote if the requested amount must reprice each week.
- Cuba's recipient-decision pattern is in `common/decisions/COLDWAR_CUB_1970_foreign_contracts.txt` and `common/decisions/COLDWAR_CUB_1970_bilateral.txt`: show the full prospective effect tooltip, keep the actual transaction in hidden execution, require pending/open mirrored receipts and the current clear-pair trigger, then set mirrored signed flags. `COLDWAR_CUB_reconcile_bilateral` in `common/scripted_effects/COLDWAR_CUB_1970_bilateral.txt` adds or removes both spirits from the paired signed flags and clear-pair trigger. Reconciliation must not replay fees or finite rewards.
- The current Cuba clear-pair triggers require existence, no bilateral war, no native embargo, and no mirrored diplomatic, financial, economic or military Imperia sanctions in either direction. Reuse the four-class bilateral lifecycle rule and its eight directional checks.
- `tools/chile_1970/validate.py` documents an available Clausewitz AST parser for emitted scripts; Chile static audits report engine testing separately. The installed HOI4 executable exists at the Steam common path. The required `E:` runtime drive is not present in this environment. I did not launch the game, as the parent owns that step.

## Native fiscal event indicators

- Observed inflation is `inflation_rate_var`, where 0.01 is 1%. `quarterly_inflation_calculation` in `common/scripted_effects/00_economic_effects.txt` appends each quarterly change to `year_quarter_inflation_tracker`, averages the last four quarters, and writes the rolling annual value. Existing `inflation_rate_higher_than_3` checks `inflation_rate_var > 0.029`; `inflation_rate_higher_than_2` checks `> 0.019`. Use the existing rate trigger for an inflation settlement. `inflation_gain_multiplier_modifier` is a policy modifier, not the measured inflation rate.
- `debt_ratio` is `debt / gdp_total`, a fraction clamped from 0 to 5; 1.0 means 100% of GDP. Existing `gdp_debt_ratio_higher_25` checks 0.25. The monthly Imperia debt action flags debt-high above 1.0 and very-high above 2.0, with a 180-day cooldown. Native tax escalation checks debt service above potential income, interest above 8, or debt ratio above 1.0, together with negative `treasury_rate`. A lower Brazil threshold is a feature-specific policy condition and should not be described as the global native crisis threshold.
- `currency_strength` is the current currency level, with par at 1.0 and a clamp of 0.15 to 2.0. `calculate_currency_strength` runs monthly and incorporates debt risk, cycle, war, sanctions, and the `recent_financial_collapse` flag. That flag is set for 1095 days by `restructure_debt_after_financial_collapse`. No general `macrocrisis` idea or trigger exists in the inspected native sources; do not make one up as a state detector.
- The oil model starts `global.imp_global_oil_price` at 75 and recalculates `global.imp_oil_price_effective` after producer and embargo multipliers. The effective price above 100 activates `imp_oil_prices_high` across countries. This is the native high-oil signal to use for a conditional oil-shock response. Guard global-variable existence before numeric checks. The triggered-only `imp_oil.7` news event is called by a separate GC decision, not automatically by a 1973 on_action.
- Only 3 of the approved 8 events are referenced by focus effects: `officer_council`, `constitution`, and `party_reform`. The other five (`oil_shock`, `debt_crisis`, `us_rights`, `party_split`, `inflation_settlement`) need explicit source actions if intended as gameplay, or the compiler should leave them unused. For an inflation settlement, a monthly BRA check against the rolling `inflation_rate_higher_than_3` trigger is materially stronger than a policy-modifier check; one-shot receipt or a long cooldown must prevent repeated pops. For an oil shock, use the native effective-price/high-modifier condition with a one-shot receipt instead of a date-only 1973 trigger.
