## France's 1970 NATO state

The local 1970 setup creates the `faction_template_1985_nato` faction under the USA, explicitly adds France to that faction, and then grants `NATO_member` to the listed Western states, including France (`common/scripted_effects/IMP_1970_world_politics_effects.txt:1205-1253`, invoked once by the global alignment initializer at `:1387-1395`). The alliance uses its own `global.nato_members` array, maintained by the `NATO_member` idea's callbacks. On add, it inserts the country once; on removal, it removes the country and marks NATO's UI state dirty (`common/ideas/Factions.txt:6-60`). `NATO_currently_exists` reads the first member-array slot, while `NATO_possible_countries` is a separate startup/eligibility set (`common/scripted_triggers/00_NATO_scripted_triggers.txt:1-24`; `common/scripted_triggers/MD_Country_Groups_Triggers.txt:1000-1028`).

Treaty membership and participation in integrated military command are separate concepts in historical France. MD has an existing France idea and focus named `FRA_distance_nato`; its localisation describes withdrawal from integrated command while remaining a treaty member. The focus adds a timed `FRA_distance_nato` idea and does not call `NATO_leave` or remove `NATO_member` (`common/national_focus/05_france.txt:5625-5665`). There is no separate native NATO integrated-command membership idea/API in the files reviewed. A new UDR command branch therefore needs a distinct custom France command-status spirit/receipt while preserving NATO membership for a command-autonomy outcome.

**Source inconsistency to avoid copying:** `FRA_distance_nato` is canceled by `has_idea = NATO_member` (`common/ideas/05_france.txt:3178-3191`), despite the focus adding it while still a member. Its lifetime and cancellation should be confirmed in-game before treating the old idea as a functional model for a permanent command status. The full-exit idea `FRA_left_nato` also cancels when NATO membership returns (`common/ideas/05_france.txt:787-795`), which is a different contract.

## Native membership, full departure, and consent

| Operation | Current API/source | Meaning for a France focus |
| --- | --- | --- |
| Admit a country directly | `NATO_join` (`common/scripted_effects/01_NATO_effects.txt:63-165`) | Checks `can_join_NATO`; updates opinion and access, adds `NATO_member`, NATO tech sharing, and faction membership under the current leader. This helper itself does not solicit every member's consent. Do not call it as a unilateral focus reward. |
| Ask a NATO leader to accept | `NATO_join_via_event` and event `NATO.14` (`common/scripted_effects/01_NATO_effects.txt:167-228`; `events/NATO_system.txt:169-212`) | Sends one accept/refuse request to the USA if it is still a NATO leader, otherwise to a current faction leader. This is a leader/sponsor decision, not the whole alliance's consent. |
| Run accession with all members' approval | `become_NATO_aspirant`, `finish_NATO_membership_action_plan`, `ratify_country_accession`, `join_NATO` (`common/decisions/NATO.txt:264-289,508-558,611-740`) | Each existing `NATO_member` can ratify the candidate and records `NATO_Ratified_@FROM`; the final decision requires all existing members to ratify, ignoring vanished countries. Only then does it call `NATO_join`. This is the source-backed pattern if the proposed agreement represents accession to full NATO membership and must not treat USA alone as all NATO. A 1970-specific bypass/availability and France's permanent-departure gates need separate review. |
| Leave NATO entirely | `NATO_leave` (`common/scripted_effects/01_NATO_effects.txt:230-302`) | Removes membership idea and NATO technology-sharing group, transfers leadership if needed, leaves the faction, clears mutual NATO opinion/military-access relations, and issues the departure news event. The `NATO_member.on_remove` callback removes the array entry. A focus that says full withdrawal should call this; do not simulate departure by only removing a modifier. |
| Rejoin integrated command | Existing French `FRA_rejoin_nato_command` decision (`common/decisions/France.txt:5733-5782`) | Removes `FRA_distance_nato` and `FRA_strategic_independance` and improves allied opinions. It does not call `NATO_join`, add `NATO_member`, or reactivate `FRA_NATO_support`; it is command/relationship restoration only, not treaty accession. |

The full withdrawal focuses call `NATO_leave` and then grant `FRA_left_nato` (`common/national_focus/05_france.txt:4072-4106` and `:8789-8832`). The modern France full-exit path can set `FRA_left_nato_permanently`; the NATO applicant decision explicitly blocks that flag (`common/decisions/NATO.txt:264-271`). Current sources show no France-specific, all-member re-accession implementation that reverses this permanent-exit contract. If the new UDR tree allows France to leave treaty membership and later seek readmission, that re-entry must be designed as a new integration. If it only restores integrated command while France remains a treaty member, do not run `NATO_leave`/`NATO_join` and do not route consent through an irrelevant USA-only event.

## Compatible route baseline to check against new nodes

A static scan of the current 134-node concept gives a UDR whole-route independent maximum of about -0.06 supply consumption, +0.20 equipment-cost multiplier, +0.08 army training-time factor, +0.11 army organization, +0.08 core defence, and +0.09 organization regain when the old Atlantic Training agreement is included. Air-training XP gain reaches +0.12 with that agreement; the same idea contributes -0.02 foreign influence. These maxima are per-key envelopes after prerequisites/exclusions, not a single guaranteed campaign route. They show why the new branch should target logistics, planning, limited doctrine choices and training, and why adding positive equipment expense or more generic organization/defence would stack poorly.

Before reviewing final new nodes, recompute the actual selected-route sum, including its UDR branch choices, shared defence choices, NATO agreement/membership spirits, and Atlantic Training bilateral spirit. Count only compatible foci/treaties and include removals/departure behavior. For caps, distinguish MD's explicit 100-point influence share headroom, limited-use research/doctrine counts, and modifiers for which no script cap was found. Static source arithmetic is not an engine simulation.

## Source-supported versus newly designed

- **Source-supported native operations:** `NATO_join`, `NATO_leave`, `NATO_member` and its membership array callbacks, current NATO candidate/ratification decisions, `add_doctrine_cost_reduction`, `add_tech_bonus`, country modifiers above, and the MD money/influence consumers.
- **Not an existing native France treaty/command API:** a separate, persistent command-integration state while retaining `NATO_member`; all-member consent specifically for readmitting France to integrated command; any UDR-specific proposal, committee, command assignment or recurring command program; and a permanent fix for the old timed `FRA_distance_nato` state/cancel mismatch. These require new custom design/runtime code and must not be described as source-native behavior.
- **Consent boundary:** `NATO.14` is one leader's decision. Full NATO accession's `ratify_country_accession` plus final all-member `join_NATO` gate is the available native precedent for whole-alliance consent. A new command integration agreement is custom and should collect the intended NATO-member approvals rather than letting USA alone speak for the alliance.

No source test or live-game test was run for this report. The line references support code structure and current formulas; faction membership changes, temporary idea cancellation timing, native hovers, and 1970 multiplayer behavior remain engine-level checks.
