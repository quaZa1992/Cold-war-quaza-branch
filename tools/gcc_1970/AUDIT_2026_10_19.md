### Original P1 — Native membership array contains unsigned governments at scenario startup

`common/on_actions/00_on_actions.txt:1747` calls `setup_global_arrays` without
a scenario restriction. `common/scripted_effects/00_startup_effects.txt:228`
through line 233 inserts SAU, QAT, UAE, BHR, KUW and OMA into
`global.gcc_member_state` without checking `idea_gcc_member_state`.

The new 1970 agreement correctly gives the membership spirit only to governments
that sign. The programme refresh checks actual membership, but currently does
not reconcile the native array. The native idea's `on_add`/`on_remove` callbacks
in `common/ideas/Factions.txt:114` cannot remove a stale entry belonging to a
country that never had the spirit. The generic removal helper at
`common/scripted_effects/01_international_systems_effects.txt:2916` is called
from the annexation cleanup in `common/on_actions/MD_on_actions.txt:417`, not
from the new 1970 startup or daily membership refresh.

Player-visible consequence: `GCC_offer_joint_exercises_specific` in
`common/decisions/Gulf.txt:971` iterates this array and sends `gcc.26` to every
existing country except the origin, without a membership test. A council of two
actual signatories can therefore offer exercises to the other four unsigned
governments. The exercise grant also uses the array plus an accepted flag rather
than actual membership. Native expulsion voting similarly sends ballots through
the array to existing non-target countries, admitting unsigned governments into
the procedure.

Recommended bounded repair: in the 1970 scenario, synchronize each of the six
founders' array entries against its actual membership spirit, before native
consumers run and when membership changes. Do not clear the entire array:
consensual native accession by other countries must not be destroyed. Add a
regression that begins with all six native startup entries and only two actual
membership spirits, rather than treating `add_ideas` as the whole native
membership lifecycle.

## Verified current requirements and transactions

- All fourteen installed focuses, including `COLDWAR_GCC_council`, visibly
  require the membership spirit and independence. The hidden runtime guard also
  checks scenario, country, UAE proclamation and delivered prerequisites.
  `COLDWAR_GCC_can_apply_council` at
  `common/scripted_triggers/COLDWAR_GCC_1970.txt:38` uses the actual member
  trigger. Every reward helper rechecks its corresponding guard.
- Founding is reachable first: the decision and category use sovereign status,
  not `COLDWAR_GCC_done_council`. Independent, eligible nonmembers can negotiate
  membership before starting the member-only branch. Protected or unproclaimed
  UAE cannot use this entry route.
- Admission events freeze separate origin and recipient contributions at 2% of
  each country's GDP. They require a current, unexpired, same-round offer for the
  actual partner; acceptance rechecks funds, independence, government, war and
  recipient nonmembership. Refusal pays nothing and removes no membership.
- Acceptance can charge the origin only if it is still a new member. Another
  origin's prior accepted offer makes the recipient ineligible for double
  charging. Stale rounds cannot clear the current pending offer.
- Programme costs do not impose a focus treasury prerequisite. All costs and
  one-time XP/PP gains use delivered receipts. Dynamic programme contributions
  and the technical group suspend on membership/sovereignty loss and return from
  earned receipts without replaying payments or XP.
- The new technical group permits sovereign members that earned technical
  standards, without requiring the original Saudi-led military faction.
- New focus IDs and new completion flags do not invoke the native forced
  faction, puppeting or annexation chains. The native $25bn arms package is
  hidden only in the 1970 scenario by the bounded legacy adapter.
- Dominant-member departure repair preserves unity and a valid successor. The
  independent tests exercise departure and return without replaying assets.

## Verification and limits

The current `test_integration.py` passes eight groups, including all six hosts,
all fourteen focus guards, negative-balance cost application, suspension/return,
founding-before-focus, concurrent invitations, stale rounds and leadership
succession. The array issue above is **not covered by that simulator**, which
models native idea commands explicitly and does not execute the entire native
startup array initializer. Existing passing tests therefore do not resolve it.

No new admission race, focus membership-gate bypass or duplicate grant was found
in the audited source. Engine loading, exact hovers, event rendering, save
migration and actual multiplayer synchronization remain unobserved.
